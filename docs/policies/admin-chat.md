## 1. 목적
사용자(회원·비회원)가 서비스에서 진행한 **AI 매체추천 대화 로그를 관리자가 조회**하는 읽기 전용 화면이다. 목록에서 누가 얼마나 대화했는지 집계로 보고, 상세에서 실제 대화 내용(사용자 발화 ↔ AI 응답 + 추천된 매체)을 확인한다.

- 핵심 사용자: `chat` 권한을 가진 관리자(또는 마스터)
- 성공 기준: ❓
- 이 화면은 **조회 전용**이다. 대화 삭제·수정·응답 등 쓰기 동작은 이 화면에 없다(백엔드 `admin_chat.py`는 GET 3종만 제공).

## 2. 권한

접근 권한은 **`chat` 메뉴 권한을 가진 관리자**. 마스터 계정은 권한 설정과 무관하게 전체 허용. 상세 정책은 [관리자 인증·권한 정책](admin-auth-permissions.md) 참조.

| 사용자 | 접근 | 비고 |
|---|---|---|
| 마스터 계정 | 전체 허용 | 권한 설정 무관 |
| `chat` 권한 보유 관리자 | 목록·상세 조회 | |
| `chat` 권한 없는 관리자 | 사이드바 메뉴 미노출 + API 403 | 프론트 게이팅은 UX, 실제 방어는 백엔드 |

- 백엔드 3개 엔드포인트 모두 `require_permission("chat")` 가드 적용: `GET /admin/chat/overview`, `GET /admin/chat/users/{user_id}`, `GET /admin/chat/sessions/{session_id}`.
- 프론트는 axios 인터셉터가 `admin_token`을 자동 첨부.

## 3. UI 블록

### 3.A 목록 화면 (`/admin/chat`)

#### 3.A.0 페이지 헤더
- **기능**: 화면 제목 표시.
- **규칙**: 고정 텍스트 "AI 채팅 관리".

#### 3.A.1 검색바
- **기능**: 이름·이메일 키워드로 목록 행을 필터.
- **규칙**:
  - 입력 필드 1개(placeholder "이름·이메일로 검색").
  - **클라이언트 필터**: 이미 받아온 전체 행에서 `name` 또는 `email`에 키워드가 포함(`includes`)된 행만 남긴다. 서버 재조회 없음.
  - 공백만 입력하면(trim 후 빈 값) 필터 해제 → 전체 노출.
  - 비회원 행은 이름="비회원", 이메일="-"이라 키워드 검색으로는 사실상 걸러지지 않음 ❓(비회원 검색 요구사항).

#### 3.A.2 대화 집계 테이블 (CommonTable)
- **기능**: 사용자별 AI 채팅 사용 집계를 행으로 나열. 행 클릭 시 상세로 이동.
- **규칙**:
  - 컬럼: `No` / `이름` / `이메일` / `대화방 수` / `메시지 수` / `마지막 사용일`.
  - **행 구성 규칙(백엔드 `list_chat_overview`)**:
    - **회원 행**: `user_id`가 연결된 세션들을 **회원 1명당 1행으로 집계**. `대화방 수`=해당 회원 세션 개수, `메시지 수`=세션 메시지 합계, `마지막 사용일`=세션 중 가장 최근 `updated_at`. 행 key = `user_id`.
    - **비회원 행**: `user_id`가 없는 세션은 **세션마다 1행**. 이름="비회원", 이메일="-", `대화방 수`=1. 행 key = `session_id`.
  - **정렬**: 마지막 사용일(`last_used_at`) 내림차순(최근 순). 회원/비회원 섞여 정렬됨.
  - `No`는 정렬 후 화면 인덱스(1부터). 데이터 값이 아니라 표시 순번.
  - `대화방 수`·`메시지 수`는 천단위 콤마 포맷. `마지막 사용일`은 `YYYY.MM.DD HH:mm`, 파싱 실패 시 "-".
  - **페이지네이션**: `usePageSizeSelect` + 기본 `pageSize=10`. 총건수는 필터 적용 후 행 수(`filtered.length`).
  - **행 클릭**: `/admin/chat/{key}?kind={member|guest}`로 이동. kind는 행 종류에 따라 부착.
  - 데이터 조회 훅 `useAdminChatOverview`는 `staleTime` 30초.
- `❓` 목록에는 페이지 크기 select만 있고 서버 페이지네이션이 아니라 전체 로드 후 클라이언트 처리 — 데이터 급증 시 성능 정책.

#### 3.A.3 빈/로딩 상태
- **규칙**: 로딩 중이면 테이블 empty 문구 "불러오는 중...", 데이터 0건이면 "대화 내역이 없습니다.".

### 3.B 상세 화면 (`/admin/chat/[id]`)

라우트 파라미터 `id`(회원=user_id, 비회원=session_id)와 쿼리 `kind`로 회원/비회원 상세를 분기한다. `kind`가 `member`가 아니면 모두 `guest`로 취급.

#### 3.B.0 페이지 헤더
- **기능**: 화면 제목.
- **규칙**: 고정 텍스트 "AI 채팅 상세".

#### 3.B.1 회원 상세 (`kind=member`)
- **기능**: 회원 1명의 프로필 + 대화방 목록 + 선택 대화방의 메시지 로그.
- **규칙**:
  - **프로필 카드**: 이름, 멤버십 뱃지(`individual`→"개인", `corporate`→"기업", 그 외 원문), 이메일, "대화방 N" 표시. 데이터 로딩 중 이름 자리에 "불러오는 중...".
  - **대화 목록 패널(좌측, 고정폭)**: 헤더 "대화 목록 N". 각 세션 행 = 제목 + `updated_at`(포맷) + "메시지 N". 세션이 없으면 "대화 내역이 없습니다.".
  - **세션 선택**: 기본 선택 = 목록 첫 번째 세션(`sessions[0]`). 다른 행 클릭 시 선택 변경(활성 행 강조).
  - **메시지 테이블(우측)**: 선택된 세션의 메시지 로그(3.B.3 공통 테이블).
  - 데이터 출처: `useAdminChatUser(user_id)`(프로필+세션 목록) + `useAdminChatSession(활성 세션 id)`(메시지).

#### 3.B.2 비회원 상세 (`kind=guest`)
- **기능**: 단일 비회원 세션의 메시지 로그.
- **규칙**:
  - **세션 카드**: 이름 "비회원" 고정 + `{세션제목} · 생성 {created_at} · 메시지 {개수}` 요약.
  - 대화 목록 패널 없음(세션 1개). 바로 메시지 테이블 노출.
  - 데이터 출처: `useAdminChatSession(session_id)`.

#### 3.B.3 메시지 로그 테이블 (회원·비회원 공통)
- **기능**: 한 세션의 대화 메시지를 순서대로 표시.
- **규칙**:
  - 컬럼: `순번` / `역할` / `대화 내용` / `시간`.
  - `역할`: 백엔드 `role`이 `user`면 "사용자", 그 외(`assistant`)는 "AI".
  - `순번`: 배열 인덱스 기반 1부터. 메시지는 `messages` 배열 순서대로(생성순).
  - `대화 내용`:
    - 본문 텍스트(`content`) 표시(줄바꿈 유지). content가 없으면 "-".
    - **AI 추천 매체 블록**: 메시지 `payload.items`(추천 매체 배열)가 있으면 별도 박스로 "추천 매체 N건: 1. 매체명 / 2. 매체명 ..." 표시.
    - `payload.match_count`(전체 매칭 수)가 노출 건수보다 크면 "추천 매체 {match_count}건 중 {노출수}건 노출" 형식.
    - 매체명은 `payload.items[].name`, 없으면 "(매체명 없음)". rank는 배열 순서(1부터).
  - `시간`: `created_at`을 `YYYY.MM.DD HH:mm`로.
  - **페이지네이션**: `pageSize=50`, 검색바 없음(`useSearch=false`). 로딩 중 "불러오는 중...", 0건이면 "메시지가 없습니다.".

#### 3.B.4 목록으로 버튼
- **기능**: 목록 화면으로 복귀.
- **규칙**: 클릭 시 `/admin/chat`로 이동.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 목록 로딩 | overview 조회 중 | 테이블 "불러오는 중..." |
| 목록 성공 | 행 ≥ 1 | 집계 테이블(페이지 10개) |
| 목록 결과 없음 | 데이터 0건 또는 검색 0건 | "대화 내역이 없습니다." |
| 상세 회원 로딩 | user 조회 중 | 프로필 "불러오는 중...", 목록 "불러오는 중..." |
| 상세 세션 로딩 | session 조회 중 | 메시지 테이블 "불러오는 중..." |
| 상세 성공 | 메시지 ≥ 1 | 메시지 로그 테이블 |
| 상세 메시지 없음 | 세션 메시지 0건 | "메시지가 없습니다." |
| 상세 회원 세션 없음 | 회원에 세션 0개 | 대화 목록 "대화 내역이 없습니다.", 우측 메시지 테이블 빈 상태 |
| 404 | user/session 미존재 | 백엔드 404 반환 ❓(프론트 에러 표시 UI 미확인) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 대화 집계 목록 | `GET /admin/chat/overview` (`require_permission("chat")`) | 목록 진입 시. 회원 집계 + 비회원 세션 행 |
| 회원 상세(프로필+세션) | `GET /admin/chat/users/{user_id}` | 상세(kind=member) 진입 시 |
| 세션 메시지 로그 | `GET /admin/chat/sessions/{session_id}` | 세션 선택/비회원 상세 진입 시 |
| 원본 테이블 | `ad_sessions` / `ad_messages` (+ `users` 조인) | 세션은 익명 생성 가능(user_id nullable) |
| AI 추천 매체 payload | `ad_messages.payload`(`items`, `match_count`) | assistant 메시지에 `recommend_v2`가 기록 |

- 세션은 사용자 미로그인 상태에서도 생성되므로(`user_id` nullable) 비회원 대화가 존재한다.
- `React Query` staleTime 30초(overview/user/session 공통).
