---

## 1. 목적
로그인한 회원이 자기 계정 정보를 확인하고(아이디·회사이름·이름·전화번호), 비밀번호·프로필 항목을 변경하며, 사업자등록증을 등록하고, 마케팅 수신 동의를 토글하고, 로그아웃/회원 탈퇴를 수행하는 계정 관리 화면이다.

- 핵심 사용자: 로그인한 회원(개인/기업)
- 성공 기준: ❓

## 2. 권한
로그인 회원 전용. 화면 데이터는 `GET /auth/me`(Bearer 토큰)로 조회하며, 토큰이 없으면 `useMe` 쿼리가 비활성(`enabled: !!getUserToken()`)이라 사용자 정보가 로드되지 않는다. 라우트 자체의 미로그인 리다이렉트 가드는 이 화면 코드에는 없음 ❓(상위 layout/proxy 처리 여부 미확인).

개인/기업 회원(`membership_type`) 구분이 데이터에는 있으나, 이 화면의 UI 동작은 등급별로 분기하지 않는다(모든 회원 동일 UI).

## 3. UI 블록 (위 → 아래)

화면은 좌측 사이드바(`Sidebar`)와 상단 모바일 네비(`MobileTopNav`) 안에서 본문(`ProfileView`)이 세로 스크롤되는 구조다. 본문은 최대 폭 1016px 중앙 정렬.

### 3.0 페이지 헤더
- **기능**: 화면 제목 영역.
- **규칙**: "계정 정보" 제목 + "회원 정보 및 계정 설정을 관리할 수 있습니다." 부제 고정 노출.

### 3.1 프로필 카드 (이름·이메일 + 로그아웃)
- **기능**: 로그인 사용자의 이름/이메일 표시 + 로그아웃 버튼.
- **규칙**:
  - 이름은 `me.name`(공백뿐이면 빈 문자열), 이메일은 `me.email`.
  - **로그아웃**: 로컬 저장된 refresh 토큰이 있으면 `POST /auth/logout`으로 서버 폐기 시도(best-effort, 실패해도 무시). 이후 로컬 토큰 삭제(`clearUserToken`) + `me` 쿼리 캐시 제거 + 홈(`/`)으로 이동.

### 3.2 아이디 행 (읽기 전용)
- **기능**: 계정 아이디 표시.
- **규칙**: `me.email`을 아이디로 노출. **변경 버튼 없음(수정 불가).**

### 3.3 계정 항목 리스트 (비밀번호·회사이름·이름·전화번호)
- **기능**: 항목별 현재 값 표시 + "변경" 링크로 각 모달 열기.
- **규칙**:
  - 4개 행: **비밀번호**(값 `**********` 마스킹), **회사이름**(`company_name`), **이름**(`name`), **전화번호**(`phone`, 11자리면 `010-0000-0000` 포맷으로 표시).
  - 각 행의 "변경" 클릭 → 해당 모달 오픈(`password` / `company` / `name` / `phone`). 한 번에 하나만 열림.
  - 값이 없으면 빈 문자열로 표시.

  - **3.3.1 비밀번호 변경 모달** (`PasswordChangeModal`)
    - 입력 3개: 현재 비밀번호 / 새 비밀번호 / 새 비밀번호 확인(모두 `type=password`).
    - 새 비밀번호 규칙: **영문·숫자·특수문자 모두 포함 + 8자 이상**(정규식 `(?=.*[A-Za-z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}`). 미충족 시 필드 에러.
    - 새 비밀번호 ≠ 확인값이면 확인 필드에 "새 비밀번호가 일치하지 않습니다." 에러.
    - 제출 → `POST /auth/change-password`(`current_password`, `new_password`). 성공 시 토스트 "비밀번호가 변경되었습니다." + 모달 닫힘.
    - 실패 시: 응답 `status===400` 또는 detail에 "현재 비밀번호" 포함이면 현재 비밀번호 필드에 "현재 비밀번호가 올바르지 않습니다.", 그 외는 일반 실패 메시지. (백엔드는 현재 비밀번호 불일치 시 400 반환.)
    - 제출 버튼 활성 조건: 세 필드 모두 입력됨 + 요청 진행 중 아님. 닫으면 입력값 초기화.

  - **3.3.2 회사이름 / 이름 / 전화번호 변경 모달** (`TextFieldModal` 공용)
    - 단일 입력 + "변경하기" 버튼.
    - 제출 → `PATCH /auth/me`(해당 필드만, 값은 trim). 성공 시 `me` 무효화 + 토스트 "변경되었습니다." + 닫힘.
    - 버튼 활성 조건: 값 trim 후 길이 > 0 **AND** 기존값과 다름 **AND** 요청 중 아님.
    - **전화번호**: `inputMode=numeric`, `maxLength=11`, 검증 `^\d{11}$`(- 없이 11자리 숫자). 서버 409(중복) 시 "이미 사용 중인 전화번호입니다." 그 외 실패는 일반 메시지. (백엔드: 다른 유저가 같은 전화번호 보유 시 409.)
    - `defaultValue`가 바뀌면 `key`로 모달을 리마운트해 입력 초기값을 최신 값으로 맞춘다.

### 3.4 사업자등록증 행 + 등록/변경 모달
- **기능**: 사업자등록증 상태·파일 표시 + 상태별 액션(등록/변경/취소).
- **규칙**:
  - `me.business_registration`(`status`·`license_file_url`·`license_file_name`·`license_uploaded_at`) 기반 표시. 상태 뱃지: **미등록**(grey) / **검토중**(주황 `#fff3d3`/`#ff920a`) / **검토 완료**(민트 `#e5f6f6`/`#00aaa4`) / **인증 반려**(빨강 `#ffe1df`/`#ff2c20`). ※ 유저단은 reviewing을 "검토중"으로 표기 — admin은 동일 상태를 "검토 대기"로 표기(admin-members §3.7).
  - **미등록**: "등록된 사업자등록증이 없습니다." + 우측 **"등록"** 버튼.
  - **검토중/검토완료/반려**(파일 존재): 파일 정보 블록 — 공용 컴포넌트 `LicenseFileInfo`(파일 아이콘 + **업로드한 원본 파일명** `license_file_name` + **업로드 시각** `license_uploaded_at`), 클릭 시 파일 새 탭 열림. 상태별 부가:
    - **검토중**: 안내 "변경시, 검토 후 3영업일 이내 담당자가 확인 후 반영이 됩니다." + 우측 **"취소"** → 확인 다이얼로그 후 `DELETE /auth/me/business-registration`(파일 삭제 + 미등록 복귀, Figma 1100:27796).
    - **인증 반려**: **"인증 반려 사유 : {reject_reason}"**(빨강 `#ff6c64`) + 우측 **"변경"** (Figma 1100:28626).
    - **검토 완료**: 우측 **"변경"** (Figma 1115:36415). → **혜택**: 사업자 인증(`verified`) 회원은 제안서 생성 **무제한** + AI 채팅 **무제한**(미인증은 각각 5건 / 100회 제한). [proposals §2](proposals.md) · [ai-media-recommend](ai-media-recommend.md) 참조.
  - **업로드 모달(`BusinessRegisterModal`)**: `mode`(register/change) 분기 — 미등록이면 제목 "사업자등록증 **등록**"·"**등록하기**", 등록됨이면 "사업자등록증 **변경**"·"**변경하기**".
    - **빈 상태**: 점선 드롭존(원형 배지 아이콘 `public/icons/business-upload.svg` + "파일을 드래그하거나 클릭하여 업로드" + "PDF 형식, 최대 10MB"). **클릭·드래그앤드롭** 지원, 드래그 중 primary 하이라이트.
    - **파일 선택 시**: `LicenseFileInfo` 파일 칩 + ✕ 삭제(Figma 1100:27541).
    - 안내 박스 + 10MB 검증. 제출 → `POST /auth/me/business-registration`(multipart) → 사업자등록 상태 **`reviewing`** 전환 + `me` 무효화 + 모달 닫힘. 업로드 시 원본 파일명·업로드 시각 저장(마이그 032).

### 3.5 마케팅 정보 수신 동의 (토글)
- **기능**: 마케팅 수신 동의 on/off.
- **규칙**:
  - 표시값 = 낙관적 오버라이드(`marketingOverride`) ?? `me.marketing_consent` ?? false.
  - 토글 즉시 낙관적 반영 후 `PATCH /auth/me`(`marketing_consent`). 성공 시 `me` 무효화, 실패 시 이전 상태로 롤백.
  - 요청 진행 중에는 스위치 비활성.

### 3.6 회원 탈퇴 블록
- **기능**: 계정 영구 삭제.
- **규칙**:
  - "회원 탈퇴" 버튼 → 확인 다이얼로그(`useConfirm`): 제목 "회원 탈퇴를 하시겠습니까?", 설명 "계정 삭제는 영구적이며 돌이킬 수 없습니다. 사용자님의 데이터는 30일 이내에 삭제됩니다.", 확인 버튼 "탈퇴".
  - 확인 시 → `DELETE /auth/me`. 백엔드는 **하드 삭제가 아니라** 유저 `status`를 `withdrawn`으로 변경 + `withdrawn_at` 기록 + 해당 유저의 유효 refresh 토큰 전부 폐기(soft-delete). (탈퇴 계정은 이후 로그인 시 403 "탈퇴한 계정입니다.")
  - 성공 시 로컬 토큰 삭제 + `me` 캐시 제거 + 홈(`/`) 이동.
  - 실패 시 확인 다이얼로그로 "회원 탈퇴에 실패했습니다." 안내.
  - UI 안내문("30일 이내 삭제")과 실제 구현(soft-delete, 물리 삭제 로직 미확인)의 정합성 ❓.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 정상 | `me` 로드 완료 | 각 항목에 값 표시 |
| 로딩 | `me` 조회 중 | 별도 로딩 UI 없음 — 값이 빈 문자열로 렌더 ❓ |
| 미로그인 | 토큰 없음 | `useMe` 비활성으로 `me` undefined, 전 항목 공란 ❓(가드 미확인) |
| 모달 열림 | 변경/등록 클릭 | 해당 모달 1개만 노출 |
| 변경 실패 | API 4xx/5xx | 모달 내 필드 에러 또는 실패 토스트/다이얼로그 |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 프로필(이메일·이름·전화·회사·마케팅동의 등) | `GET /auth/me` (`useMe`) | 진입 시, staleTime 5분, 토큰 있을 때만 |
| 프로필 수정 | `PATCH /auth/me` (`useUpdateProfile`) | 이름/회사/전화/마케팅 변경 시 |
| 비밀번호 변경 | `POST /auth/change-password` | 비밀번호 모달 제출 |
| 회원 탈퇴 | `DELETE /auth/me` (soft-delete: status=withdrawn) | 탈퇴 확인 시 |
| 로그아웃 | `POST /auth/logout` (best-effort) + 로컬 토큰 삭제 | 로그아웃 버튼 |
| 사업자등록증 조회 | `GET /auth/me`의 `business_registration` | 진입 시. 상태·`license_file_url` 표시 |
| 사업자등록증 업로드 | `POST /auth/me/business-registration` (multipart, `useUploadBusinessRegistration`) | 등록/변경 모달 제출. 로컬 디스크 저장(`/uploads/business/{user_id}/…`) + 원본 파일명·업로드 시각 기록, 상태 `reviewing` 전환 |
| 사업자등록증 검토 취소 | `DELETE /auth/me/business-registration` (`useCancelBusinessRegistration`) | 검토중 "취소" 확인 시. 파일 삭제 + 미등록 복귀 |
