# 제안서 목록 (고객) 화면 정책서 (UI중심)

> **이 문서는 "이 화면이 어떤 규칙으로 동작하는가"를 정의합니다.**
> 화면을 위→아래 **UI 블록 순서**로 읽습니다. 각 블록은 **"무엇 + 동작 규칙"**만 적고, 디자인(색·여백·컴포넌트 모양)은 Figma에 둡니다. 미정은 줄 안에 `❓`로 표시하고 맨 아래 "미정" 섹션에 한 번 더 모읍니다.

| | |
|---|---|
| **화면** | 제안서 목록 (내 제안서) · `/proposals` |
| **진입** | LNB "내 제안서" 클릭 · 매체 "제안서 담기" 후 이동 등 ❓(진입 경로 확정 필요) |
| **Figma** | ❓(미확인) |
| **상태/작성자** | `draft` · (코드 기반 자동생성) · 2026-07-09 |

## 1. 목적
사용자가 담아둔(생성한) 제안서들을 한 곳에서 조회·검색·필터하고, 새 제안서를 만들거나 삭제·다운로드하며, 카드 클릭으로 상세 편집 화면으로 진입하는 목록 화면이다.

- 핵심 사용자: 옥외광고 매체를 골라 제안서를 만드는 광고주/마케터 (비회원 포함)
- 성공 기준: ❓ (미정)

## 2. 권한
접근은 **전체 사용자**(비회원 포함). 소유 기준이 회원/비회원에 따라 다르고, 제안서 **생성 개수 한도**와 **다운로드 권한**이 등급별로 갈린다 (코드 근거: `proposal_service.py`, `ProposalsView.tsx`).

| 사용자 | 소유 기준 | 생성 한도 | 한도 도달 시 (409) | 다운로드 |
|---|---|---|---|---|
| 비회원(guest) | 브라우저 `session_id` | **1건** (`GUEST_LIMIT`) | "한도 1건 소진" 다이얼로그 → `회원가입하기` → `/signup` | ❌ (로그인 유도 다이얼로그) |
| 회원(member, 사업자 미인증) | 회원 토큰(`member_id`) | **5건** (`MEMBER_LIMIT`) | "한도 5건 소진, 사업자 인증 시 무제한" 다이얼로그 → `프로필 이동` | ✅ |
| 인증회원(verified, 사업자등록 `verified`) | 회원 토큰 | **무제한** (`None`) | — | ✅ |

- 목록은 소유자별로만 조회된다: 회원이면 세션 무시(`member_id` 기준), 비회원이면 `session_id` 기준. 소유자 키가 없으면 빈 목록.
- 다운로드는 `isMember()`(회원 토큰 존재) 기준. 비회원이 다운로드 클릭 시 "로그인 후 다운로드" 다이얼로그(`로그인 화면으로`)만 뜨고 실제 다운로드는 막힌다.

## 3. UI 블록 (위 → 아래)

화면은 세로로 **① 헤더(제목 + 새 제안서) → ② 탭 + 검색 → ③ 카드 그리드(또는 로딩/빈 상태) → ④ 새 제안서 모달**로 구성된다. 컨테이너 최대폭 1016px, 중앙 정렬.

### 3.0 헤더 (제목 + 새 제안서 버튼)
- **기능**: 화면 제목 "내 제안서"와 우측 `새 제안서` 버튼.
- **규칙**:
  - `새 제안서` 클릭 → 새 제안서 모달(3.4) 오픈.

### 3.1 탭 (상태 필터)
- **기능**: `전체 / 작성중 / 제출완료 / 맞춤제안 / 계약완료` 5개 탭으로 목록을 상태별로 거른다. 기본 선택 `전체`.
- **규칙**:
  - **클라이언트 측 필터**(추가 API 호출 없음). 백엔드 원본 상태를 UI 탭으로 매핑:
    - `contracted` → **계약완료**
    - `execution_requested` → **제출완료**
    - `custom` → **맞춤제안**
    - 그 외(`new` 등) → **작성중**
  - `전체` 탭은 모든 상태 노출.
  - 검색어(3.2)와 **AND** 조건으로 함께 적용된다.
  - 삭제(논리삭제)된 제안서는 목록 응답 자체에서 제외되어 어떤 탭에도 나타나지 않는다(3.3.2 참조).

### 3.2 검색창 (제안서명 검색)
- **기능**: 제안서 제목으로 목록을 좁힌다. placeholder "검색어를 입력하세요."
- **규칙**:
  - **클라이언트 측 부분일치**: 입력값을 trim한 뒤 `title.includes(keyword)` (대소문자 구분, 공백만 입력 시 무시).
  - 실시간 필터(입력 즉시 반영). 탭 필터와 AND.

### 3.3 카드 그리드 (제안서 목록)
- **기능**: 필터를 통과한 제안서를 카드로 나열. 데스크톱 3열, 모바일 1열.
- **규칙**: 목록 데이터는 `GET /proposals?session_id=`로 조회(React Query, staleTime 10초). `updated_at` 내림차순(최신 수정 순)으로 서버 정렬.
- 카드 1장 구성/동작:
  - **3.3.1 썸네일**: 현재 모든 카드가 고정 이미지 `/proposals/sample.png`를 표시(제안서별 실제 미리보기 아님) ❓.
  - **3.3.2 삭제 버튼**(썸네일 위 휴지통): 클릭 시 카드 클릭 전파를 막고(`stopPropagation`) 확인 다이얼로그("제안서를 삭제하시겠습니까?", 제목 강조) → 확인 시 `DELETE /proposals/{id}` 후 목록 갱신.
    - **삭제 처리(상태별로 다름)**:
      - `new`(작성중): **완전삭제**(행 제거) — 관리자에 노출된 적 없는 초안.
      - `execution_requested`(제출완료)·`custom`(맞춤제안): **논리삭제 → `cancelled`(취소)** 로 전환. 관리자에 "취소"로 노출.
      - `contracted`(계약완료): **상태 유지 + 삭제 시각(`deleted_at`) 기록**. 관리자에 "계약완료 + 삭제됨"으로 노출(성사된 계약 이력 보존).
    - 어느 경우든 유저 목록·상세에서 사라지고, 삭제된 건은 제안서 **생성 한도에서도 제외**된다(삭제 후 새 제안서 생성 가능). 관리자 표시 규칙은 [admin-proposals.md](admin-proposals.md) 참조.
  - **3.3.3 제목 + 최종 수정일시**: 제목 1줄 말줄임. "최종 수정 {updatedAt}", 형식 `YYYY.MM.DD HH:mm`(값 없으면 `-`).
  - **3.3.4 상태칩**: 백엔드 원본 상태를 라벨/색으로 표시 (`StatusChip`, 고객 목록·상세 공통):
    - `new` → 작성중 / `execution_requested` → 제출완료 / `custom` → 맞춤제안 / `contracted` → 계약완료 / `cancelled` → 취소
    - 알 수 없는 값은 `작성중`으로 폴백. **관리자 화면은 별도 라벨**을 사용한다(예: `execution_requested`를 "신규"로 표시) — [admin-proposals.md](admin-proposals.md).
  - **3.3.5 다운로드 버튼**: 클릭 시 전파 차단 후 다운로드(2번 권한 참조). 회원이면 `GET /proposals/{id}/export-ppt`(python-pptx 생성, 최대 60초)로 Blob을 받아 `{제목}.pptx`로 저장. 다운로드 진행 중인 카드 버튼은 비활성(중복 클릭·동시 다운로드 방지), 실패 시 조용히 무시(별도 에러 노출 없음) ❓.
  - **3.3.6 카드 클릭**(썸네일/제목 영역): 상세 화면 `/proposals/{id}`로 이동.

### 3.4 새 제안서 모달
- **기능**: 제안서명을 입력해 새 제안서를 생성한다.
- **규칙**:
  - 이름 입력(placeholder "제안서 이름을 입력해 주세요."). `생성` 버튼은 **공백 제외 입력이 있어야만 활성**.
  - `생성` 클릭 → `onCreate(trim된 이름)` 호출, 입력 초기화 후 모달 즉시 닫힘.
  - 실제 생성: `POST /proposals`(title + session_id). 성공 시 목록 무효화→재조회. 제목은 서버에서 trim 후 최대 300자, 빈 값이면 "새 제안서"로 저장.
  - **생성 한도 초과(409, `limit_reached`)**: 모달은 닫힌 뒤(낙관적으로 먼저 닫힘) 티어별 한도 다이얼로그가 뜬다(2번 표 참조). guest는 회원가입, member는 프로필 이동 유도.
  - X 또는 바깥 닫기 시 입력값 초기화.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 로딩 | 목록 조회 중(`isLoading`) | "불러오는 중..." 중앙 문구 |
| 빈 상태(empty) | 조회 성공·소유 제안서 0건 | "아직 제안서가 없어요. 새 제안서를 만들어보세요." |
| 결과 없음 | 필터/검색 통과 0건 (원본은 존재) | 빈 상태와 **동일 문구** 사용(별도 "검색 결과 없음" 없음) ❓ |
| 성공(result) | 필터 통과 1건 이상 | 카드 그리드 |
| 제한 도달 | 생성 시 409 | 티어별 한도 다이얼로그(3.4) |
| 에러 | 목록 조회 실패 | 별도 에러 UI 없음 ❓ / 다운로드 실패는 무시 |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 제안서 목록 | `GET /proposals?session_id=` (React Query `myList`, staleTime 10s) | 진입 시. `updated_at` desc 정렬 |
| 제안서 생성 | `POST /proposals` | 모달 `생성`. 409 시 `limit_reached`+tier+limit |
| 제안서 삭제 | `DELETE /proposals/{id}` | 카드 휴지통 확인 후 |
| PPT 다운로드 | `GET /proposals/{id}/export-ppt` (Blob, timeout 60s) | 카드 다운로드(회원 전용). `{제목}.pptx` |
| 소유자 판별 | 회원 토큰(`getUserToken`) / 비회원 `session_id`(`getSessionId`) | 목록·생성·삭제 공통 |
