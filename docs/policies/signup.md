## 1. 목적
아우라웍스 계정을 새로 만들어 회원 등급(개인/기업)에 맞는 권한을 부여하는 화면이다. `/signup`에서 가입 방식(소셜·이메일·기업)을 고르고, 이메일/기업은 전용 폼으로 이동해 정보를 입력·검증한 뒤 가입한다. 가입 성공 시 곧바로 로그인 상태가 되어 홈(`/`)으로 이동한다.

- 핵심 사용자: 옥외광고 매체를 찾으려는 신규 광고주/마케터(개인·기업)
- 성공 기준: ❓

## 2. 권한
전체 사용자(비회원)가 접근 가능. 가입 시 `membership_type`으로 **개인(individual) / 기업(corporate)** 등급이 결정된다. 가입 성공 시 access/refresh 토큰이 즉시 발급되어 로그인 완료 상태가 되며, 등급별 권한·토큰 한도는 각 기능 화면 정책서를 따른다.

| 사용자 | 접근 | 결과 |
|---|---|---|
| 비회원 | 가입 화면 접근 가능 | 가입 완료 시 즉시 로그인(토큰 발급) 후 홈 이동 |

> 가입 API(`POST /auth/register`)는 `remember=true`로 토큰을 발급한다(로그인 유지 30일 상당). 또한 `session_id`를 넘겨 **비회원 세션에서 담았던 제안서를 신규 회원 계정으로 이관**한다(`claim_session_proposals`).

## 3. UI 블록 (위 → 아래)

화면은 **① 가입방식 선택(`/signup`) → ② 이메일/기업 가입 폼(`/signup/email`·`/signup/corporate`)** 두 단계로 나뉜다. 이메일 폼과 기업 폼은 **동일 컴포넌트(`SignupForm`)를 `membershipType` prop으로 분기**해 재사용한다.

### 3.0 가입방식 선택 (`/signup`)
- **기능**: 로고 + 안내 문구 + 개인/기업 탭 + 가입 시작 버튼 + "로그인" 링크.
- **규칙**:
  - **개인/기업 탭**: 기본값 **개인 회원**. 탭 클릭으로 하단 버튼 구성이 바뀐다.
  - **개인 탭 선택 시** 버튼 3개 노출:
    - `카카오로 시작하기` / `네이버로 시작하기` → 소셜 가입(3.3).
    - `이메일로 시작하기` → `/signup/email`로 이동.
  - **기업 탭 선택 시** 버튼 1개: `기업회원으로 가입 시작하기` → `/signup/corporate`로 이동. (기업 탭에는 소셜 버튼 없음)
  - 하단 "이미 회원이신가요? **로그인**" 링크 → 홈(`/`)으로 이동. ❓(로그인 진입은 `/login`이 아니라 `/`로 연결됨 — 의도 확인 필요)

### 3.1 이메일(개인) 가입 폼 (`/signup/email`)
- **기능**: 이메일·비밀번호·이름·전화번호 입력 + 약관 동의 + `가입 완료`.
- **규칙**: 필드 구성/검증은 3.4(공통 폼 규칙) 참조. `membershipType="individual"` — 회사명·사업자등록증 블록 없음.

### 3.2 기업 가입 폼 (`/signup/corporate`)
- **기능**: 이메일 폼의 모든 항목 + **회사명(필수)** + **사업자등록증 업로드**.
- **규칙**: `membershipType="corporate"`. 공통 항목은 3.4 참조. 기업 전용 항목:
  - **회사명**(필수): 공백만 입력 시 "회사명을 입력해 주세요." 에러. `company_name`으로 전송.
  - **사업자등록증 업로드**(Figma 반영): 파일 선택 시 **테두리 칩**(파일 아이콘 + 파일명 + ✕ 삭제)이 나타나고, 그 아래 회색 **"파일 업로드"** 버튼이 상시 노출된다. 안내 "사업자 인증 시 AI 추천을 더욱 원활하게 이용할 수 있습니다." → **선택 항목**(필수 아님). 파일은 `register` payload에는 포함되지 않고, **가입 완료(토큰 발급) 직후** `POST /auth/me/business-registration`(multipart)로 업로드된다. 업로드 실패해도 가입은 유지되며 마이페이지에서 재등록 가능(profile §3.4). 업로드 시 사업자등록 상태 `reviewing`.

### 3.3 소셜 가입 (카카오 / 네이버, 개인 탭)
- **기능**: 소셜 계정으로 가입 시작.
- **규칙**:
  - 버튼 클릭 → `GET /auth/sns/{provider}`로 인가 URL을 받아 `window.location.href`로 리다이렉트(외부 로그인). 요청 중 두 버튼 비활성화(`snsPending`), 실패 시 다시 활성화.
  - 인증 후 `/oauth/[provider]/callback`로 복귀해 토큰 교환(`snsExchange`) → 로그인 처리. 최초 소셜 계정은 **자동 회원가입**(추가 입력 없음)으로 처리됨(로그인 정책서 §3.4와 동일). 세부 콜백 처리·약관 동의 수집 여부는 ❓.
  - 소셜 자동가입 사용자의 기본 등급은 ❓(개인 추정).

### 3.4 공통 가입 폼 규칙 (`SignupForm`)
React Hook Form + Zod(`zodResolver`)로 검증. 필수 항목 라벨에 `*` 표시. 에러 시 해당 입력 테두리/배경 강조 + 하단 빨간 문구.

- **이메일**(필수): 빈 값 "이메일을 입력해 주세요.", 형식 위반 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` "이메일 형식이 올바르지 않습니다."
- **비밀번호**(필수): 정규식 `(?=.*[A-Za-z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}` — 영문·숫자·특수문자 모두 포함 8자 이상. 위반 시 "영문, 숫자, 특수문자를 모두 포함해 8자 이상 입력해 주세요."
- **비밀번호 확인**(필수): 빈 값 "비밀번호를 한번 더 입력해 주세요.", 원본과 불일치 시 "비밀번호가 일치하지 않습니다."
- **이름**(필수): 빈 값 "이름을 입력해 주세요."
- **전화번호**(필수): `-` 없이 **11자리 숫자**(`/^\d{11}$/`), maxLength 11·숫자 입력모드. 위반 시 "전화번호는 '-' 없이 11자리 숫자로 입력해 주세요."
- **회사명**: 기업 폼에서만 필수(3.2).

### 3.5 약관 동의 블록
- **기능**: 전체 동의 + 개별 항목 5개.
- **규칙**:
  - **전체 약관 동의**: 체크 시 5개 전부 on/off 토글.
  - **필수 4개**: `[필수] 만 14세 이상입니다.` / `[필수] 서비스 이용약관 동의` / `[필수] 개인정보 처리방침 동의` / `[필수] 위치기반 서비스 이용약관 동의`.
  - **선택 1개**: `[선택] 마케팅 정보 수신 동의` → 값이 `marketing_consent`로 전송됨.
  - 이용약관·개인정보·위치기반 3개 항목엔 우측 chevron(상세 열람 유도)이 있으나 **연결 동작 미구현** ❓.
  - 필수 4개를 모두 체크하지 않고 `가입 완료`를 누르면 폼 검증과 별개로 "필수 약관에 모두 동의해 주세요." 노출 + 제출 중단.

### 3.6 가입 완료 버튼 / 제출 처리
- **기능**: 폼 제출 → `POST /auth/register`.
- **규칙**:
  - 제출 순서: Zod 필드 검증 → 필수 약관 체크 확인 → API 호출.
  - payload: `email, password, name, phone, membership_type, company_name(기업만), marketing_consent, session_id`. (사업자등록증 파일은 미포함 — 가입 성공 후 별도 multipart 업로드, 3.2)
  - 성공: `setTokens(access, refresh, true)`로 토큰 저장 → `authKeys.me` 무효화 → `router.replace("/")`(홈).
  - 요청 중(`isPending`) 버튼 비활성 + 회색 처리(중복 제출 방지).
  - **중복 처리(409)**: 응답 detail에 "전화번호" 포함 시 전화번호 필드에 "이미 가입된 전화번호입니다.", 그 외 409는 이메일 필드에 "이미 가입된 이메일입니다." (백엔드가 이메일·전화번호 중복을 각각 409로 반환)
  - 409 외 에러(네트워크·5xx 등) 처리는 ❓(현재 별도 사용자 안내 없음).

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 가입 | `POST /auth/register` | `가입 완료` 클릭. 성공 시 토큰 반환 + 세션 제안서 이관 |
| 소셜 인가 URL | `GET /auth/sns/{provider}` | 카카오/네이버 버튼 클릭 |
| 소셜 토큰 교환 | `GET /auth/sns/{provider}/callback` | `/oauth/[provider]/callback`에서 처리 |
| 세션 제안서 이관 | `claim_session_proposals(session_id)` | 가입 성공 시 서버측 자동 |
| 사업자등록증 업로드 | `POST /auth/me/business-registration` (multipart) | 기업 가입 + 파일 선택 시, 토큰 발급 직후(best-effort). 상태 `reviewing` |

> 백엔드 검증: 이메일 중복 409 "이미 가입된 이메일입니다.", 전화번호 중복 409 "이미 가입된 전화번호입니다."(`phone` unique). `User.membership_type` 기본값 individual.
