## 1. 화면 목적 (Why)

광고주가 자연어로 광고 조건을 입력하면, 챗봇이 대화를 통해 조건을 모아 최적의 OOH(옥외광고) 매체를 추천해 주는 화면이다. 검색 폼을 채우는 대신 대화로 매체를 찾고, 추천 결과를 기획안으로 이어가게 한다.

- **핵심 가치**: 광고 지식이 없어도 대화만으로 적합한 옥외광고 매체를 찾는다.
- **주 사용자**: 광고를 집행하려는 광고주(비회원 ~ 기업회원).
- **성공 기준**: 추천 리스트 도달률, 추천 → 기획안 생성 전환율.

## 2. 사용자 & 권한 정책

채팅 사용량은 사용자 등급에 따라 다르며, **채팅 토큰(발화 횟수)** 으로 제한한다.

| 사용자 구분 | 접근 | 제한 / 한도 | 한도 도달 시 동작 |
|---|---|---|---|
| 비회원 | 채팅 사용 가능 | **채팅 토큰 5회** | 5회 소진 시 추가 발화 차단 → **로그인 유도** |
| 개인회원 | 채팅 사용 가능 | **30회** | 소진 시 추가 발화 차단 → 안내(상위 등급/기업 전환 등) |
| 기업회원 (사업자 미등록) | 채팅 사용 가능 | **100회** | 소진 시 추가 발화 차단 → **사업자 등록 유도** |
| 기업회원 (사업자 등록 완료) | 채팅 사용 가능 | **무제한** | 해당 없음 |

> **카운팅 규칙 (논의 필요 — 9번 참조)**: 무엇을 1회로 셀지(사용자 발화 1건 = 1회 가정), 리셋 주기(누적/월/일), 비회원→회원 전환 시 잔여 횟수 처리 방식은 아직 미확정.

## 3. 핵심 기능 (What)

### 3.1 매체 추천 챗봇

- **무엇을**: 사용자의 자연어 발화에서 광고 조건(슬롯)을 추출하고, 조건이 충분해지면 매체를 추천한다.
- **동작 규칙**: 발화 → 슬롯 추출 → 슬롯 개수 판단 → 부족하면 추가 질문, 충분하면(2개 이상) 추천 리스트 생성.
- **제약**: **슬롯이 2개 이상** 모여야 추천 리스트를 만든다. 그 전까지는 조건을 더 요청한다.

### 3.2 추천 리스트

- **무엇을**: 조건에 맞는 매체 목록을 카드 형태로 제시한다.
- **동작 규칙**: 슬롯 2개 이상 충족 시 생성. 결과가 있으면 리스트 + 지도를 함께 노출하고, 이어서 **기획안 생성을 권유**한다.
- **제약**: 결과 0건이면 리스트 대신 "결과 없음" 안내.

### 3.3 지도 표시

- **무엇을**: 추천된 매체의 위치를 지도에 표시한다.
- **동작 규칙**: **추천 리스트가 발생할 때** 지도 표시가 함께 트리거된다.
- **제약**: 추천 결과가 없으면 지도는 표시되지 않거나 기본 상태.

### 3.4 기획안 생성 권유

- **무엇을**: 추천 리스트 이후 기획안 생성으로 넘어가도록 유도한다.
- **동작 규칙**: 추천 리스트 노출 직후 권유 메시지/액션 노출.
- **제약**: (기획안 생성 가능 조건/권한은 기획안 화면 정책서에서 정의 — 논의 필요)

## 4. 사용자 플로우 (How)

```
탭 진입
 └─ 채팅 입력
     ├─ 토큰 잔여 없음              → 발화 차단 + 등급별 유도(로그인/사업자등록)
     └─ 토큰 잔여 있음 → 슬롯 추출
          ├─ 슬롯 0~1개            → 조건 더 요청 (추가 질문)
          └─ 슬롯 2개 이상
               ├─ 결과 0건         → "결과 없음" 안내
               └─ 결과 있음        → 추천 리스트 + 지도 표시 → 기획안 생성 권유
```

핵심 단계별 규칙:

1. **진입** — 채팅 인터페이스 노출. 등급에 따른 잔여 토큰 상태 반영.
2. **발화 입력** — 토큰 잔여 확인이 먼저. 없으면 등급별 유도 동작으로 분기.
3. **슬롯 추출** — 발화에서 광고 조건을 추출해 누적.
4. **추천 판단** — 슬롯 2개 이상이면 추천, 아니면 조건을 더 요청.
5. **결과 노출** — 결과가 있으면 리스트 + 지도 동시 표시.
6. **다음 행동 권유** — 기획안 생성으로 유도.

## 5. 화면 상태 정의

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 빈 상태(empty) | 첫 진입, 대화 없음 | 입력 가이드/예시 발화 노출 |
| 로딩(loading) | 추천 검색 중 | 검색 중 표시(스피너 등) |
| 조건 부족 | 슬롯 0~1개 | 조건을 더 요청하는 메시지 |
| 성공(result) | 슬롯 2개+ & 결과 있음 | 추천 리스트 + 지도 + 기획안 권유 |
| 결과 없음 | 슬롯 2개+ & 결과 0건 | "조건에 맞는 매체가 없습니다" 안내 |
| 제한 도달(limit) | 잔여 토큰 0 | 발화 차단 + 등급별 유도(로그인/사업자등록) |
| 에러(error) | 통신/서버 오류 | 오류 안내 + 입력 보존 (논의 필요) |

## 6. 비즈니스 규칙 / 정책

- 채팅 토큰 한도 — 비회원 **5회**, 개인회원 **30회**, 기업회원(사업자 미등록) **100회**, 기업회원(사업자 등록) **무제한**.
- 토큰 소진 시 추가 발화를 **차단**하고 등급별 유도 동작 실행: 비회원 → 로그인, 기업 미등록 → 사업자 등록.
- 추천 리스트는 **슬롯 2개 이상** 충족 시에만 생성한다.
- 추천 리스트 발생 시 **지도 표시를 함께 트리거**한다.
- 추천 리스트 노출 후 **기획안 생성을 권유**한다.
- **검색 대상(믹시 검색 표 `media_items`)**: 믹시는 매체 표가 아니라 `media_items` 의 키워드 코드(업종·제품·목적·타깃·지역·카테고리, 사전 `media_keywords`)로 매체를 고른다. 매체를 만들거나 고칠 때(어드민 저장·사진 변경·엑셀 일괄 등록)마다 `ai_index` 가 그 매체의 줄을 맞춘다(없으면 만든다, 매체 삭제 시 함께 삭제). 전체 다시 맞추기: `python -m scripts.sync_ai_index`(도입 시·사전/규칙 변경 시).
  - 코드 = 엑셀에서 온 원본(`source_codes`, 마이그레이션 048 에서 보관) + 자동 태그(합집합). 자동 태그:
    - 지역: 주소·매체명(이동매체는 운행 지역·노선)의 낱말을 지역 사전과 맞춤. 짧은 낱말은 통째·역/동/구가 붙은 꼴만("강남대로"는 강남 아님), 3글자 이상은 포함되면.
    - 카테고리: 매체 카테고리(소분류, 없으면 대분류)·매체명.
    - 업종: 인기 업종(`popular_type`).
    - 타깃: 어드민에서 직접 고른 타깃(`media.target_codes`, 마이그레이션 049)이 있으면 그것. 없으면 인구(직접 입력 월평균 → 서울시 상권, 실시간은 쓰지 않음)에서 비율이 가장 높은 연령대 1개 + 한쪽 성별 55% 이상이면 그 성별 + 장소 규칙(오피스→직장인, 대학→대학생, 공항·기차·호텔·관광→관광객, 쇼핑몰·아파트·마트·백화점·키즈→주부·가족).
    - 제품·목적은 자동으로 만들지 않는다(엑셀 원본만).
  - 매체를 지우면 검색 표 줄도 함께 지워진다(외래키 ON DELETE CASCADE, 마이그레이션 050).
- **어드민 입력(노출·검색 구역)**: "인기 업종"은 업종 사전에서 여러 개 선택(값은 사전 첫 낱말, `popular_type` 에 "화장품, 패션"으로 저장 — 예전 자유 입력값 중 사전에 없는 건 "(목록에 없음)"으로 보이고 풀 수 있다). "타깃"은 타깃 사전에서 여러 개 선택(비면 자동). 보기 전용 "자동 추천 타깃"·"AI 검색 태그"(저장된 값 기준, `GET /admin/media/{id}` 의 `ai_preview`). 선택지는 `GET /admin/media/field-options` 의 `industries`·`targets`.
- **검색 규칙(`recommend_react/domain.filter_media_items`)**:
  - 반드시 맞아야 하는 것: 지역(LOC)·예산. 카테고리(CAT)는 고객이 말했을 때만 — 단 검색어가 매체 글자에 있으면 카테고리가 달라도 통과("트럭"인데 카테고리는 전광판).
  - 맞을수록 위로(점수): 검색어 낱말마다 3점, 업종·제품·목적·타깃 각 1점. 점수 → (연령 발화면 연령 일치·유동인구) → 광고비 순. 태그가 비어 있는 매체도 빠지지 않는다.
  - 사전에 없는 코드(모델이 지어낸 "LOC-기차역" 등)는 버린다. 다 버려져 조건이 없으면 "못 찾음".
  - 검색어(`keywords`): 고객이 원하는 매체 자체의 형태·설치 장소·특징인데 사전에 딱 맞는 코드가 없는 낱말(트럭·래핑·엘리베이터 TV 등)은 억지로 코드로 바꾸지 않고 검색어로 받는다. 광고할 제품·캠페인 내용(팝업스토어 오픈 등)은 검색어가 아니라 제품·목적 코드로. **검색어가 매체 글자에 있는 매체가 하나라도 있으면 그 매체만 남긴다**("트럭 매체 알려줘" → 트럭 매체만), 하나도 없으면 검색어는 무시(0건 방지). 여러 낱말이면 나누고, 일반 낱말(광고·매체·홍보·근처 등)·한 글자는 버린다. 매체명·구분명·소분류 카테고리·운행 지역·노선·지역 라벨·설명·검색 태그에서 글자로 찾는다(대분류 "공항/기차"는 넓어서 제외). 표기 차이(랩핑↔래핑, 팝업스토어→팝업 등)도 함께 찾는다.
- **추천 개수·순서**: 사용자가 개수를 말하면("강남 매체 2개 추천해줘", "하나만") SearchMedia 의 `count` 로 받아, 추천 순 위에서 그만큼만 화면 카드로 보내고 답변도 그 매체로 한다. 개수를 말하지 않으면 상위 top_k(20)건. 답변에서 매체를 짚을 때는 목록 1번부터 순서대로(화면 카드 순서와 같게) — 단 최저가·비교처럼 사용자가 기준을 준 경우는 그 기준대로.
  - 진행(2026-10-12): ① 자동 태그·검색 표 연결 ② 어드민 인기 업종 선택형·타깃 칸 ③ 검색 규칙 변경 — 모두 완료.
