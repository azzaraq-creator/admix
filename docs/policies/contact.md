# 문의하기 / FAQ 화면 정책서 (UI중심)

> **이 문서는 "이 화면이 어떤 규칙으로 동작하는가"를 정의합니다.**
> 화면을 위→아래 **UI 블록 순서**로 읽습니다. 각 블록은 **"무엇 + 동작 규칙"**만 적고, 디자인(색·여백·컴포넌트 모양)은 Figma에 둡니다. 미정은 줄 안에 `❓`로 표시하고 맨 아래 "미정" 섹션에 한 번 더 모읍니다.

## 1. 목적
고객이 **실시간 상담(카카오/네이버톡)·전화·문의 접수** 중 하나로 문의를 남기고, **자주 묻는 질문(FAQ)**으로 스스로 해결하며, 로그인 회원은 **내 문의 내역과 답변**을 확인하는 고객지원 화면이다.

- 핵심 사용자: 매체/제안 관련 문의가 있는 광고주·마케터 (비회원 포함)
- 성공 기준: `❓`

## 2. 권한
접근은 **전체 사용자**(비회원 포함). 로그인 여부(`USER_TOKEN_COOKIE` 존재)로 노출 탭과 문의 접수 방식이 갈린다.

| 사용자 | 탭 | 문의 접수 카드 | 문의 내역 |
|---|---|---|---|
| 비회원 | 문의 접수 · 자주 묻는 질문 (2개) | "메일주소 복사"(email@gmail.com) — **로그인 문의 작성 폼 사용 불가** | 없음 |
| 로그인 회원 | 문의 접수 · 문의 내역 · 자주 묻는 질문 (3개) | "문의 작성하기"(모달) | 있음(본인 것만) |

- 문의 작성 폼 제출(`POST /inquiries`)은 `get_current_user` 필요 → **로그인 필수**. 비회원은 폼 진입 자체가 없고 메일 복사로 안내.
- 문의 내역·상세(`GET /inquiries`, `GET /inquiries/{id}`)는 본인(`member_id` 일치) 것만. 타인/미존재는 404.
- FAQ 조회는 공개. 클라이언트는 **published(발행)된 FAQ만** 조회(`published_only=true`).

## 3. UI 블록 (위 → 아래)

### 3.0 헤더
- **기능**: 화면 제목/설명.
- **규칙**: 제목 "문의하기", 부제 "궁금한 내용을 확인하거나 문의를 남겨보세요." 고정 텍스트.

### 3.1 탭 바 + 검색 입력
- **기능**: 하위 화면 전환 탭. FAQ·문의 내역 탭에서만 우측에 검색 입력 노출.
- **규칙**:
  - 탭: 비회원 `문의 접수`/`자주 묻는 질문`, 회원 `문의 접수`/`문의 내역`/`자주 묻는 질문`. 최초 활성 탭은 항상 **문의 접수**.
  - 검색 입력은 `자주 묻는 질문` 또는 `문의 내역` 탭에서만 노출. 입력값(`searchQuery`)은 탭 전환 시 초기화되지 않고 그대로 유지된다(두 탭이 같은 state 공유). `❓` 의도된 동작인지 확인 필요.
  - 검색은 클라이언트 측 필터링(디바운스 없이 입력 즉시 반영).

### 3.2 문의 접수 탭 — 상담 카드 3종
가로 3장 카드(반응형으로 wrap). 각 카드는 아이콘/제목/설명 + 하단 액션.

- **① 실시간 상담 카드** (강조, "가장 빠른 상담" 뱃지)
  - **기능**: 카카오톡/네이버톡 상담 진입.
  - **규칙**: `카카오톡 상담`·`네이버톡 상담` 버튼. "평균 응답 시간 10분 이내" 안내. 두 버튼 모두 **onClick 미연결** — 실제 연결 링크/딥링크 `❓`(미구현).
- **② 전화 문의 카드**
  - **기능**: 전화번호 안내 + 복사.
  - **규칙**: 번호 `02-1234-5678`(하드코딩), 운영시간 "평일 09:00~18:00 (주말·공휴일 휴무)". `전화번호 복사` 클릭 시 `navigator.clipboard`로 복사 후 토스트("복사가 완료되었습니다."). 실제 번호/운영시간 확정값 `❓`.
- **③ 문의 접수 카드** (로그인 여부로 분기)
  - **기능**: 회원=문의 작성 모달 열기 / 비회원=메일주소 복사.
  - **규칙**: 회원이면 `문의 작성하기` → 모달(3.5). 비회원이면 이메일 `email@gmail.com` 노출 + `메일주소 복사`. 문의 유형 안내 3종: **매체 및 상품 문의 / 견적 및 제안 관련 문의 / 기타 문의**(안내 텍스트일 뿐, 폼에서 유형 선택 필드는 없음).

### 3.3 문의 접수 탭 — "문의 전 확인해 보세요" 배너
- **기능**: FAQ로 유도.
- **규칙**: `자주 묻는 질문 보기` 클릭 시 활성 탭을 `faq`로 전환.

### 3.4 문의 접수 탭 — 안내 사항
- **기능**: 정적 안내 문구.
- **규칙**: 2개 고정 문구 노출("실시간 상담은 운영시간 내 이용", "로그인 사용자 문의는 고객지원 > 문의 내역에서 확인").

### 3.5 문의 작성 모달 (회원 전용)
- **기능**: 로그인 회원이 문의를 접수.
- **규칙**:
  - 오버레이 클릭 또는 X로 닫힘. 폼 영역 클릭은 전파 차단.
  - **프리필**: 로그인 정보(`useMe`)로 이름/이메일/전화/회사 초기값 채움. `me`가 늦게 도착하면 `key` 변경으로 remount되어 초기값 재계산.
  - **필드**: 이름*·이메일*·전화번호*·회사(선택)·제목*·내용*(textarea). (*=필수)
  - **유효성**(제출 시도 후 실시간): 이름/제목/내용 공백 불가, 이메일 정규식(`^[^\s@]+@[^\s@]+\.[^\s@]+$`), 전화번호 `-` 없이 **정확히 11자리 숫자**(`^\d{11}$`). 위반 시 필드별 에러 메시지 + 에러 스타일.
  - **제출**: `POST /inquiries` (subject/content/name/email/phone/company). 성공 시 모달 닫힘 + 내 문의 목록 캐시 무효화. 제출 중 버튼 비활성("제출 중..."). 성공/실패 토스트나 별도 완료 안내는 없음 `❓`(성공 피드백 부재).
  - 서버는 항상 `status=pending`으로 생성. 문의 유형 값은 저장하지 않음.

### 3.6 문의 내역 탭 (회원 전용)
- **기능**: 본인 문의 목록.
- **규칙**:
  - `GET /inquiries`로 본인 문의를 **최신순** 조회. 각 행: 상태 칩 + 제목 + `>` 아이콘.
  - 상태 칩: `answered`="답변 완료"(secondary), 그 외(pending)="답변 대기".
  - 검색어는 **제목(subject)만** 부분일치 필터.
  - 빈 상태: 검색 결과 0건="검색 결과가 없습니다.", 문의 0건="접수한 문의가 없습니다." (로딩 중에는 빈 상태 미노출).
  - 행 클릭 시 문의 상세 화면(3.8)으로 이동.

### 3.7 자주 묻는 질문(FAQ) 탭
- **기능**: 발행된 FAQ 목록/카테고리 필터/검색/펼침.
- **규칙**:
  - `GET /faqs?published_only=true`로 발행 FAQ만 조회.
  - **카테고리 칩**: `전체`·`이용안내`·`매체검색 & 제안서`. 서버 `faq_type`("이용 안내"/"매체검색&제안서")을 클라이언트 라벨로 매핑, 매핑 없으면 원본 `faq_type` 그대로 표시. 카테고리는 **단일 선택**, 기본 `전체`.
  - **검색**: 질문(title) 또는 답변(content) 부분일치. 카테고리 필터와 AND 결합.
  - **아코디언**: 각 항목 +/X 토글로 답변 펼침. **여러 항목 동시 펼침 가능**(Set으로 관리). 답변은 `whitespace-pre-line`으로 줄바꿈 보존.
  - FAQ 정렬은 서버 `sort_order`, `created_at` 순. 결과 0건 시 전용 빈 상태 없이 목록만 비어 노출 `❓`.

### 3.8 문의 상세 화면 (회원 전용, 별도 뷰)
- **기능**: 내 문의 1건 + 답변 표시.
- **규칙**:
  - `inquiryId` 설정 시 제목/탭/검색이 사라진 **단독 화면**으로 전환(같은 라우트 `/contact` 내 state 전환, URL 변화 없음). `❓` 새로고침 시 목록으로 복귀(딥링크 불가).
  - `뒤로가기` 클릭 시 목록 탭으로 복귀.
  - `GET /inquiries/{id}`로 본인 문의 상세 조회. 상단에 상태 칩.
  - **문의 정보**: 이름/이메일/전화번호/회사/제목/제출일(`YYYY.MM.DD HH:mm`)/문의 내용(pre-wrap). 값 없으면 "-".
  - **답변 영역**: `answer` 있으면 답변자명(없으면 "ADMIX 고객지원")·답변일·답변 본문 표시. 없으면 "정상 접수되었습니다. 담당자 확인 후 답변 예정" 안내.

### 3.9 토스트
- **기능**: 복사 완료 등 일시 알림.
- **규칙**: 화면 하단 중앙 고정, 2초 후 자동 사라짐 + `확인` 버튼으로 즉시 닫기. 현재 트리거는 전화번호/메일주소 복사뿐.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 기본(문의 접수) | 최초 진입 | 상담 카드 3종 + 배너 + 안내 사항 |
| FAQ 목록 | FAQ 탭 | 카테고리 칩 + 검색 + 아코디언 목록 |
| FAQ 결과 없음 | 검색/필터 0건 | 전용 빈 상태 없이 목록만 빔 `❓` |
| 문의 내역(회원) | 내역 탭 | 본인 문의 목록(최신순) |
| 내역 빈 상태 | 문의 0건 / 검색 0건 | "접수한 문의가 없습니다." / "검색 결과가 없습니다." |
| 문의 모달 | 회원 "문의 작성하기" | 프리필 폼 + 유효성 검사 |
| 문의 상세 | 내역 행 클릭 | 단독 화면(문의+답변) |
| 로딩 | 목록/상세 조회 중 | 별도 스켈레톤/스피너 없음 `❓` |
| 에러 | 조회/제출 실패 | 전용 에러 UI 없음 `❓` |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 로그인 여부 | `USER_TOKEN_COOKIE` (서버컴포넌트) | 진입 시 탭/카드 분기 |
| 프리필 정보 | `GET /me` (`useMe`) | 문의 모달 열 때 |
| FAQ 목록 | `GET /faqs?published_only=true` | FAQ 탭, staleTime 60s |
| 내 문의 목록 | `GET /inquiries` | 내역 탭, staleTime 30s |
| 내 문의 상세 | `GET /inquiries/{id}` | 상세 진입 시 |
| 문의 접수 | `POST /inquiries` | 모달 제출, 성공 시 목록 캐시 무효화 |
| 카카오/네이버톡 | 미연결 | 버튼 onClick 없음 `❓` |
| 전화번호/이메일 | 하드코딩(02-1234-5678 / email@gmail.com) | 복사 기능만 동작 |
