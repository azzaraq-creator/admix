# 관리자 제안 관리 화면 정책서 (UI중심)

> **이 문서는 "이 화면이 어떤 규칙으로 동작하는가"를 정의합니다.**
> 화면을 위→아래 **UI 블록 순서**로 읽습니다. 각 블록은 **"무엇 + 동작 규칙"**만 적고, 디자인(색·여백·컴포넌트 모양)은 Figma에 둡니다. 미정은 줄 안에 `❓`로 표시하고 맨 아래 "미정" 섹션에 한 번 더 모읍니다.

| | |
|---|---|
| **화면** | 관리자 제안 관리 (목록 / 상세 / 맞춤제안 작성·상세) · `/admin/proposals` |
| **진입** | 관리자 사이드바(`business` 권한 메뉴) · 목록 행 클릭 → 상세 · 상세 "맞춤제안 작성" → 작성 · 이력 행 "상세" → 맞춤제안 상세 |

---

## 1. 목적
회원/비회원이 만든 제안서(플래닝)를 관리자가 조회하고, 맞춤제안(PPT)을 업로드해 고객에게 전달하며, 집행을 수락(계약 완료 처리)하는 백오피스 화면이다. 고객이 담은 매체 항목을 코드로 슬라이드(표지→서머리→매체별→Thanks)로 재현해 미리보고 PPT로 내보낸다.

- 핵심 사용자: `business` 권한을 가진 관리자
- 성공 기준: ❓(미정)

## 2. 권한
`/admin/proposals` 하위 모든 API는 `require_permission("business")`. 마스터는 권한 설정과 무관하게 전체 허용, 일반 관리자는 `business` 권한 보유 시에만 접근(없으면 API 403). 프론트 사이드바 노출도 `business` 권한 기준. 상세 규칙은 [관리자 인증·권한 정책](admin-auth-permissions.md) 참조.

> 목록/상세 조회, 맞춤제안 업로드/다운로드, 집행 수락, PPT 내보내기 모두 동일하게 `business` 단일 권한으로 게이팅된다. 관리자별 세분 권한(조회만/수정 가능 등)은 없음.

## 3. UI 블록

### 3.A 제안 목록 (`/admin/proposals`)

#### 3.A.0 페이지 헤더
- **기능**: "제안 관리" 타이틀.
- **규칙**: 정적 텍스트.

#### 3.A.1 검색/필터 바 (CommonTable searchOptionList)
- **기능**: 목록을 조건으로 좁힌다.
- **규칙**:
  - **기간(period, dateRange)**: 필터 UI에는 존재하나 **현재 목록 필터링 로직에 반영되지 않음**(등록일 기준 기간 필터 미구현). `❓`
  - **상태(status, select)**: 옵션 `신규 / 맞춤제안 / 계약완료 / 취소`. 선택 시 해당 상태 행만 노출(클라이언트 필터). ("집행 요청" 옵션 제거됨 — 아래 매핑표 참조)
  - **키워드(keyword, text)**: 입력 문자열이 **제안서 명 또는 이름(회원명)에 포함**되면 노출(부분 일치, 대소문자 구분). placeholder "검색조건을 입력해주세요".
  - 필터링은 서버 재조회 없이 클라이언트에서 이미 받은 목록에 적용.

#### 3.A.2 상단 우측 액션 — 엑셀 다운로드
- **기능**: "엑셀 다운로드" 버튼.
- **규칙**: 현재 `onClick` 핸들러가 연결되어 있지 않아 **동작 없음**(퍼블리싱만). 다운로드 사양 미정. `❓`

#### 3.A.3 목록 테이블
- **기능**: 전체 제안서를 표로 표시.
- **규칙**:
  - 컬럼: `No · 제안서 명 · 이름 · 매체 수 · 전체 금액 합계 · 상태 · 등록일`.
  - 정렬: 서버가 **생성일 내림차순**(최신 먼저)으로 반환. 컬럼 클릭 정렬 없음.
  - 이름(회원명): 회원이 없거나 이름이 비면 `-`.
  - 전체 금액 합계: `{금액},원` 포맷(천단위 콤마 + "원").
  - 상태 배지: 상태별 색상 구분(신규/맞춤제안/계약완료/취소). 삭제된 계약완료 건은 상태 배지 옆에 **"삭제됨"** 보조 배지 추가(`deleted=true`).
  - **작성중(`new`)은 목록에서 제외**: 고객이 제출(`execution_requested`)하기 전 초안은 관리자에 노출되지 않는다. 제출 시 "신규"로 나타난다.
  - No: 필터링된 결과 기준 1부터 재부여(원본 순번 아님).
  - **페이지네이션**: 10개씩 보기(페이지 크기 select 사용), 총건수는 필터 후 개수.
  - **행 클릭** 시 상세(`/admin/proposals/{id}`)로 이동.

##### 상태 값 매핑 (백엔드 → 관리자 표시)
| 내부 상태 | 관리자 표시 | 비고 |
|---|---|---|
| `new` | (표시 안 함) | 고객 "작성중" — 목록에서 제외 |
| `execution_requested` | **신규** | 고객이 제출완료한 건 |
| `custom` | 맞춤제안 | 맞춤제안 업로드 시 자동 |
| `contracted` | 계약완료 | 집행 수락 시 |
| `cancelled` | 취소 | 고객이 제출완료/맞춤제안 상태에서 삭제 |

> - **삭제됨 배지**: 계약완료(`contracted`) 상태에서 고객이 삭제하면 상태는 유지되고 `deleted_at`이 기록되어 "계약완료 + 삭제됨"으로 표시된다(성사 계약 이력 보존). 제출완료/맞춤제안 삭제는 `cancelled`(취소)로 전환된다.
> - 관리자가 직접 바꿀 수 있는 상태는 **`custom`(맞춤제안 업로드 시 자동)**·**`contracted`(집행 수락)** 뿐. `execution_requested`(제출)·삭제(`cancelled`/`deleted_at`)는 고객 측에서 발생. `❓`(관리자용 취소/되돌리기 액션 유무 미정)

### 3.B 제안 상세 (`/admin/proposals/[id]`)

#### 3.B.1 회원 정보 카드
- **기능**: 제안서 소유 회원 정보 표시.
- **규칙**:
  - 항목: 회원 유형 · 회사명 · 이름 · 이메일 · 전화번호 · 상태(배지).
  - 회원 유형: `individual→개인`, `corporate→기업`, 그 외/없으면 `-`.
  - 비회원(세션 소유) 제안서는 `member`가 없어 모든 값 `-`. `❓`(비회원 제안 표시 정책 확정 필요)
  - 각 값이 비면 `-`.

#### 3.B.2 제안서 타이틀 + PPT 다운로드
- **기능**: 제안서 제목 표시 + 코드 생성 PPT 내려받기.
- **규칙**:
  - **PPT 다운로드** 클릭 → `GET /admin/proposals/{id}/export-ppt` 호출(타임아웃 60초). 성공 시 `{제안서명}.pptx` 파일로 저장.
  - 생성 중에는 버튼 "생성 중…" + 비활성. 실패 시 조용히 종료(에러 토스트 없음). `❓`(실패 UX 미정)
  - PPT는 python-pptx로 서버에서 생성: **표지 → 서머리(매체 5개씩 페이지 분할) → 매체별 상세 → THANK YOU** 순. 표지/Thanks는 배경 이미지(`cover-bg.png`), 서머리는 캠페인 기간/지역/광고비·제작비·전체 합계 통계 + 표, 매체 슬라이드는 썸네일 + 지도(Geoapify 정적지도, 키 없으면 "위치 정보 없음") + 상품 표.

#### 3.B.3 슬라이드 목록 + 미리보기
- **기능**: 제안서를 슬라이드 단위로 미리보기(화면 내 렌더, 파일 아님).
- **규칙**:
  - 좌측 슬라이드 목록: `표지 · 서머리(항목 5개 초과 시 "서머리 N"으로 분할) · 매체별(매체명, 없으면 "이름 없음") · THANK YOU`.
  - 우측: 선택 슬라이드를 1920:1080 비율로 렌더. 상단에 `현재/전체` 페이지 표기.
  - 서머리 페이지 크기 **5개**(백엔드 PPT 분할과 동일).
  - 확대(Maximize) 아이콘 노출되어 있으나 클릭 동작 미연결. `❓`(전체화면 미리보기 미구현)

#### 3.B.4 맞춤제안 이력 (역제안 목록)
- **기능**: 이 제안서에 업로드된 맞춤제안(PPT) 버전 목록.
- **규칙**:
  - 헤더: `제목 · 작성자 · 제안일 · 적용 상태 · 작업`.
  - 데이터 없으면 "등록된 맞춤제안이 없습니다.".
  - 정렬: 최신 업로드가 위(서버 저장 순 기준). **첫 행(index 0) = "노출중", 나머지 = "이전 버전"**.
  - 작성자: 업로드한 관리자 이름(`author_name`), 없으면 `-`.
  - 제안일: 파일 생성일 포맷.
  - **작업 버튼 2개**:
    - "상세" → `/admin/proposals/{id}/write/{counterId}`(맞춤제안 상세).
    - 다운로드(아이콘) → `GET /admin/proposals/{id}/counter-proposal/{counterId}/download`, **업로드 당시 원본 파일명**으로 저장.
  - 상단 우측 "맞춤제안 작성" 링크 → `/admin/proposals/{id}/write`.

#### 3.B.5 하단 액션 (목록 / 집행 수락)
- **기능**: 목록 복귀 + 집행 수락.
- **규칙**:
  - "목록" → `/admin/proposals`.
  - **집행 수락**: 확인 모달("집행을 수락하시겠습니까?" / "수락하면 제안서 상태가 계약 완료로 변경됩니다.") → 확인 시 `POST /admin/proposals/{id}/accept` → 상태 `contracted`(계약 완료). 성공 토스트 "집행이 수락되었습니다.".
  - 이미 계약 완료(`accepted`)면 버튼 라벨 "계약 완료" + 비활성. 진행 중에도 비활성.
  - `❓`(수락 취소/되돌리기 없음. `execution_requested`가 아니어도 수락 가능한지 상태 가드 미정 — 코드상 상태 무관하게 contracted로 덮어씀)

### 3.C 맞춤제안 작성 (역제안 업로드, `/admin/proposals/[id]/write`)

#### 3.C.1 맞춤제안서 명 입력
- **기능**: 맞춤제안 이름 입력 필드(필수 표시 `*`).
- **규칙**: `defaultValue="[맞춤제안] 광고 제안서_2026"`. **입력값은 업로드 API로 전송되지 않음**(서버는 업로드 파일명만 사용). 즉 현재 이 입력은 저장에 영향 없음. `❓`(맞춤제안서 명 실제 저장 필요 여부)

#### 3.C.2 PPT 파일 첨부(드래그앤드롭 / 선택)
- **기능**: PPT 파일 1개 스테이징.
- **규칙**:
  - 허용 확장자 `.ppt / .pptx`, 최대 **10MB**(프론트·백엔드 동일 검증).
  - 확장자 위반 → "PPT, PPTX 파일만 업로드할 수 있습니다.", 용량 초과 → "파일 크기는 10MB 이하만 가능합니다.".
  - 드래그앤드롭 또는 "파일 업로드" 버튼으로 선택. 파일 선택 후에는 파일명 표시 + "파일 변경".
  - 이 단계는 스테이징만(즉시 업로드 안 함).

#### 3.C.3 하단 액션 (이전으로 / 맞춤제안 전송)
- **기능**: 취소 복귀 + 업로드 전송.
- **규칙**:
  - "이전으로" → `/admin/proposals/{id}`.
  - **맞춤제안 전송**: 파일 없으면 비활성. 클릭 → 확인 모달("맞춤제안을 전송하시겠습니까?" / "작성한 맞춤제안이 고객에게 전달됩니다.\n전송 후에도 새로운 버전의 맞춤제안을 추가로 작성할 수 있습니다.") → 확인 시 `POST /admin/proposals/{id}/counter-proposal`(multipart).
  - 서버 처리: 파일 저장 → **PPT → 슬라이드 이미지 변환**(deck_converter, 고객 화면 미리보기용) → `ProposalCounterFile` 레코드 추가 + 제안서의 최신 버전 포인터 갱신(`counter_proposal_file_url/name/slides_url`) + **상태 `custom`(맞춤제안)으로 변경**.
  - 변환 실패 시 파일/슬라이드 롤백 + 500 "PPT 변환 실패".
  - 성공 시 스테이징 초기화 + 토스트 "맞춤제안이 전송되었습니다." + 상세로 복귀.
  - 실패 시 "전송에 실패했습니다. 다시 시도해주세요.".
  - **버전 누적**: 한 제안서에 여러 맞춤제안을 계속 추가할 수 있으며 최신이 "노출중".

### 3.D 맞춤제안 상세 (`/admin/proposals/[id]/write/[counterId]`)

#### 3.D.1 읽기 전용 정보
- **기능**: 등록된 특정 맞춤제안 버전 확인.
- **규칙**:
  - 맞춤제안서 명: **파일명에서 확장자 제거**한 값, `readOnly`.
  - PPT 파일명 표시(없으면 `-`).

#### 3.D.2 하단 액션 (이전으로 / PPT 미리보기 / 내보내기)
- **기능**: 복귀 + 슬라이드 미리보기 + 원본 다운로드.
- **규칙**:
  - "이전으로" → `/admin/proposals/{id}`.
  - **PPT 미리보기**: 변환된 슬라이드 이미지가 있을 때만 활성. 클릭 → 라이트박스로 슬라이드 이미지 전체보기(이미지 경로 `{API_BASE}{slides_url}/{image}`). 슬라이드 없으면 비활성.
  - **내보내기**: 파일이 있을 때 노출. 클릭 → `.../counter-proposal/{counterId}/download`로 **원본 PPT** 다운로드.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 목록 성공 | 제안서 ≥1 | 테이블 + 페이지네이션 |
| 목록 결과 없음 | 필터 결과 0건 | CommonTable 기본 빈 표시 `❓` |
| 상세 로딩/미로딩 | 상세 조회 전 | 값들이 빈/`-`로 렌더(명시적 로딩 UI 없음) `❓` |
| 맞춤제안 이력 없음 | counter_files 0 | "등록된 맞춤제안이 없습니다." |
| 계약 완료 | status=contracted | 집행 수락 버튼 "계약 완료"+비활성 |
| PPT 생성/전송 중 | export/upload 진행 | 해당 버튼 라벨 변경 + 비활성 |
| PPT 생성/전송 실패 | 서버 500 등 | export는 조용히 종료, upload는 에러 문구 노출 |
| 미리보기 불가 | 슬라이드 0장 | "PPT 미리보기" 비활성 |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 제안 목록 | `GET /admin/proposals` | 진입 시. 생성일 내림차순 |
| 제안 상세 | `GET /admin/proposals/{id}` | 진입 시. 회원+항목+맞춤제안 파일 |
| 맞춤제안 업로드 | `POST /admin/proposals/{id}/counter-proposal` (multipart) | 전송 시. PPT→슬라이드 변환, 상태 custom |
| 맞춤제안 원본 다운로드 | `GET /admin/proposals/{id}/counter-proposal/{counterId}/download` | 다운로드/내보내기 |
| 집행 수락 | `POST /admin/proposals/{id}/accept` | 상태 contracted |
| 제안서 PPT 내보내기 | `GET /admin/proposals/{id}/export-ppt` | python-pptx 생성, 60초 타임아웃 |
| 슬라이드 미리보기 이미지 | 정적 파일 `{slides_url}/meta.json` + 이미지 | 변환 결과 폴더 |
| 매체 지도(PPT) | Geoapify staticmap | PPT 매체 슬라이드, API 키 없으면 placeholder |
| 매체 항목 데이터 | 매체 마스터(Media/plans) join | 상세/PPT에서 항목별 규격·플랜·좌표 채움 |
