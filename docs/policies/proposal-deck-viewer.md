---

## 1. 목적
PPT/PPTX를 슬라이드 이미지로 변환한 **덱을 전체화면으로 넘겨보는 단독 뷰어**다. 좌측 썸네일 목록과 본문 슬라이드, 하단 페이지 네비게이션, 키보드 네비게이션을 제공한다.

- 핵심 사용자: 덱 URL을 받은 사람(내부 검토자 또는 외부 공유 대상) ❓ (실제 배포 대상 미확인)
- 성공 기준: ❓ (미정)

## 2. 권한
**로그인·권한 검사 없음 = 공개 접근.** 덱 ID를 알면 누구나 볼 수 있는 공유 링크 형태다.

- 근거: `frontend/proxy.ts`의 보호 라우트는 `/login`·`/signup`·`/find-account`·`/profile`뿐이고 `/deck/**`는 매처에 없음. 이 라우트는 `(client)`/`admin` 그룹 밖(`app/deck/`)에 있어 인증 레이아웃도 거치지 않음.
- 덱 ID(`[id]`)는 URL 경로 값으로, 추측 불가능성(랜덤성) 보장 여부는 덱 생성 주체에 달림 ❓. 샘플은 `sample`이라는 평문 ID.

> 접근 등급 구분 없음(단일: 누구나 열람). 별도 한도 없음.

## 3. UI
화면 전체가 **다크 테마 2단 레이아웃**이다. 좌 **① 썸네일 사이드바** + 우 **② 본문 영역(슬라이드 + 하단 네비바)**. 화면 높이·너비는 `h-screen w-screen` 전체 사용.

### 3.0 썸네일 사이드바 (좌측, 고정 폭)
- **기능**: 덱 제목 + 슬라이드 썸네일 세로 목록. 클릭으로 해당 슬라이드 이동.
- **규칙**:
  - 폭 고정(`w-56`), 세로 스크롤(`overflow-y-auto`).
  - **제목**: `meta.json`의 `title`이 있으면 상단에 표시, 없으면 제목 줄 자체를 숨김.
  - 각 썸네일 아래에 **1-based 순번**(`i + 1`) 표시.
  - 썸네일 이미지 경로: `/decks/{id}/{slide.thumb}` (예: `/decks/sample/thumb-1.png`), `loading="lazy"`.
  - **현재 슬라이드**는 파란 링/배경으로 강조(`ring-blue-500`), 나머지는 hover 시만 배경.
  - 현재 슬라이드가 바뀌면 해당 썸네일이 목록 안에서 `scrollIntoView`(nearest, smooth)로 자동 노출.

### 3.1 본문 슬라이드 (우측 상단, 가변 영역)
- **기능**: 현재 선택된 슬라이드 원본 이미지를 크게 표시.
- **규칙**:
  - 이미지 경로: `/decks/{id}/{slide.image}` (예: `/decks/sample/slide-1.png`).
  - 영역 안에서 비율 유지 축소(`max-h-full max-w-full`), 넘치면 잘림(`overflow-hidden`), 확대는 하지 않음.
  - 슬라이드 클릭·확대·라이트박스 동작 **없음**(이 화면에는 확대 오버레이가 없다). 상세 제안서 화면의 라이트박스와 다름 — 6번 참조.

### 3.2 하단 네비게이션 바 (우측 하단, 고정)
- **기능**: 이전/다음 이동 + 현재 위치 표시.
- **규칙**:
  - **`◀ 이전`**: 현재 인덱스 −1. 첫 슬라이드(인덱스 0)에서 `disabled`(흐려짐, opacity-30).
  - **`다음 ▶`**: 현재 인덱스 +1. 마지막 슬라이드에서 `disabled`.
  - **위치 표시**: `현재 / 전체` 형식(1-based, 예: `3 / 5`).
  - 인덱스는 항상 `[0, total-1]` 범위로 클램프(`goTo`가 min/max 처리) — 범위를 벗어나는 이동 요청은 무시.

### 3.3 키보드 네비게이션 (전역, window keydown)
- **기능**: 마우스 없이 슬라이드 이동.
- **규칙**:
  - 이전: `←` / `↑` / `PageUp`
  - 다음: `→` / `↓` / `PageDown` / `Space`
  - 처음으로: `Home` · 마지막으로: `End`
  - 위 키는 기본 동작 차단(`preventDefault`). 그 외 키는 무시.
  - 입력 필드 포커스 여부와 무관하게 window 전역에서 동작 ❓(이 화면엔 입력 요소가 없어 실사용상 충돌은 없음).

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 정상(result) | `public/decks/{id}/meta.json` 로드 성공 & `slides.length > 0` | 사이드바 + 본문 + 네비바 렌더 |
| 슬라이드 없음(empty) | `meta.json`은 있으나 `slides.length === 0` | 다크 배경 중앙에 "슬라이드가 없습니다." 문구만 |
| 없음(404) | `meta.json` 파일이 없거나 파싱 실패 | Next.js `notFound()` → 404 페이지 |
| 로딩 | (서버 컴포넌트에서 파일 동기 읽기) | 별도 로딩 UI 없음 — SSR로 완성된 페이지 전달 |
| 에러 | meta 외 오류 | 별도 처리 없음 ❓ (개별 이미지 로드 실패 시 대체 UI 없음, alt 텍스트만) |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 덱 메타(title, totalSlides, slides[]) | **프론트 로컬 파일시스템** `frontend/public/decks/{id}/meta.json` | 페이지 진입 시 서버 컴포넌트가 `fs.readFile`로 직접 읽음 (백엔드 API 호출 아님) |
| 슬라이드/썸네일 이미지 | `frontend/public/decks/{id}/slide-N.png`, `thumb-N.png` (정적 자산) | 브라우저가 `/decks/{id}/...` 정적 경로로 요청 |
| (덱 생성) PPT→슬라이드 변환 | 백엔드 `backend/src/services/deck_converter.py` (LibreOffice `soffice` + poppler `pdftoppm`) | `slide`=150dpi, `thumb`=50dpi로 렌더, 같은 폴더에 `meta.json` 작성 |

> **주의(코드-문서 불일치)**: 계획 문서 [`docs/plans/2026-06-02-ppt-upload-and-rendering.md`](../plans/2026-06-02-ppt-upload-and-rendering.md)는 이 화면이 백엔드 `GET /api/decks/{id}/meta.json`을 fetch하고 이미지도 `/api/decks/{id}/...`에서 받도록 설계했으나, **현재 코드는 여전히 프론트 `public/decks/`를 읽는다.** 업로드 페이지(`/deck/upload`)도 미구현. 또한 백엔드 `proposal_service.py`의 슬라이드 로직은 `upload_dir`의 meta.json을 읽어 **제안서(카운터 제안) 화면**에 쓰이며, 이 `/deck/[id]` 뷰어와는 데이터 경로가 분리돼 있음.

## 6. 미정 (Open Questions / 결정 로그)

> `/deck/[id]` 뷰어 화면 기준. 제품 결정이 필요한 항목만.

**미결정**
- [ ] 이 화면으로의 **진입 경로/링크** — 현재 앱 UI 어디에도 `/deck/[id]`로 가는 버튼이 없다. 어디서(관리자? 제안서? 이메일?) 이 URL을 공유하는가.
- [ ] **접근 범위** — 공개 링크가 의도된 정책인가. 그렇다면 덱 ID를 추측 불가능하게(랜덤/토큰) 발급하는가, 만료·회수가 필요한가.
- [ ] **Figma 프레임** — 이 다크 테마 뷰어 전용 디자인 링크(미확인).
