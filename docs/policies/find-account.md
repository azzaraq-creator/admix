## 1. 목적
가입한 이메일 주소를 입력하면 **비밀번호 재설정 안내 메일**을 보내, 로그인하지 못하는 사용자가 스스로 비밀번호를 재설정하도록 돕는 진입 화면이다. 이메일 입력 → 재설정 링크 발송까지만 담당하고, 실제 새 비밀번호 입력은 메일 링크로 진입하는 `/reset-password`에서 이뤄진다.

- 핵심 사용자: 비밀번호를 잊어 로그인하지 못하는 기존 회원
- 성공 기준: ❓ (예: 재설정 메일 발송 성공률, 요청 → 실제 재설정 완료 전환율 — 미정)

## 2. 권한
**비로그인 사용자 전용** 화면.

| 사용자 | 접근 | 비고 |
|---|---|---|
| 비로그인 | 접근 가능 | 정상 진입 |
| 로그인 상태 | 접근 불가 | `proxy.ts`가 `AUTH_ROUTES`(`/find-account` 포함)를 감지해 토큰이 있으면 `/`로 리다이렉트 |

> 근거: `frontend/proxy.ts` — `USER_TOKEN_COOKIE` 존재 시 `/find-account` 접근을 `/`로 redirect.

## 3. UI 블록 (위 → 아래)

화면은 단일 카드(모바일은 풀스크린, `sm` 이상은 `470px` 카드) 안에서 위→아래로 **① 로고 → ② 안내 문구 → ③ 이메일 입력 폼 → ④ 전송 버튼 → ⑤ 로그인으로 돌아가는 링크** 순으로 배치된다. 전송 성공 시 카드 내용 전체가 **완료 상태**로 교체된다.

### 3.0 로고
- **기능**: 상단 서비스 로고(`LogoFull`) 노출.
- **규칙**: 요청 폼 상태·완료 상태 양쪽 모두 상단에 고정 노출.

### 3.1 안내 문구 (요청 상태)
- **기능**: 이 화면의 목적 안내.
- **규칙**: 제목 "비밀번호를 잊으셨나요?" + 본문 "가입한 이메일 주소를 입력하시면 / 비밀번호 재설정 안내 메일을 보내드립니다." 고정 문구. 완료 상태에서는 노출되지 않는다.

### 3.2 이메일 입력 폼
- **기능**: 재설정 메일을 받을 이메일 주소 입력.
- **규칙**:
  - `<input type="email">` 단일 필드, 라벨 "이메일", placeholder "이메일을 입력해 주세요.".
  - 입력값을 바꾸면 기존 에러 메시지가 있을 경우 즉시 해제된다.
  - 에러 상태일 때 입력 필드 테두리·배경이 에러 스타일(빨강)로 바뀌고, 필드 아래 에러 메시지가 노출된다.
  - **클라이언트 검증**: 제출 시 이메일이 비어 있으면 API 호출 없이 "이메일을 입력해 주세요." 에러를 표시하고 중단. (형식 유효성 검사는 브라우저 기본 `type="email"`에 의존, 별도 정규식 검증 ❓)

### 3.3 전송 버튼
- **기능**: 입력한 이메일로 재설정 메일 발송 요청.
- **규칙**:
  - 클릭(폼 submit) 시 `POST /auth/password-reset/request` 호출(`requestPasswordReset(email)`).
  - 요청 중(`isPending`)에는 버튼이 비활성화되고 라벨이 "이메일 전송" → "전송 중..."으로 바뀐다.
  - **성공(200)**: 완료 상태(3.6)로 전환. 서버는 재설정 토큰을 응답에 노출하지 않고 이메일로만 발송하며, 발송은 백엔드 `BackgroundTasks`로 비동기 처리된다.
  - **미등록 이메일(404)**: 완료로 전환하지 않고, 필드 아래에 "가입되지 않은 이메일입니다." 에러 노출.
    - 근거: 서버 `create_password_reset`가 해당 이메일 회원이 없으면 토큰을 만들지 않고, 라우터가 `404 "가입되지 않은 이메일입니다."`를 던진다. 프론트는 `status === 404`를 이 문구로 매핑.
    - ⚠️ 이 동작은 **이메일 가입 여부가 노출(enumeration)**되는 트레이드오프를 UX 위해 감수한 결정이다(참조 plan §2).
  - **그 외 실패**: "전송에 실패했어요. 잠시 후 다시 시도해 주세요." 에러 노출.

### 3.4 로그인으로 돌아가는 링크 (요청 상태)
- **기능**: 로그인 화면으로 복귀.
- **규칙**: "비밀번호가 기억나셨나요?" + "로그인" 링크. 클릭 시 `/`로 이동(로그인 모달은 홈 화면 기반).

### 3.5 재설정 메일 (발송 결과물)
- **기능**: 사용자가 받는 재설정 안내 메일.
- **규칙**:
  - 제목: "[ADMIX] 비밀번호 재설정 안내".
  - 본문에 재설정 링크 `{email_link_base}/reset-password?token=…` 포함. 링크 유효시간 **60분**(TTL 3600초) 안내 문구 동봉.
  - 발송은 SMTP(STARTTLS). **SMTP 미설정 환경에서는 발송을 건너뛰고 요청은 실패시키지 않는다**(mailer가 False 반환, 예외는 로깅만) → 이 경우에도 화면은 완료 상태로 보인다.
  - ⚠️ Gmail 앱비번 발신은 초기 스팸 분류 위험 있음(참조 plan §1).

### 3.6 완료 상태 (전송 성공 후)
- **기능**: 발송 완료 안내 + 복귀 동선.
- **규칙**:
  - 폼·안내 문구가 사라지고 "입력하신 이메일로 / 재설정 안내 메일을 전송했습니다." 문구로 교체.
  - "로그인으로 돌아가기" 버튼(`Link href="/"`) 노출.
  - **재전송·재시도 버튼 없음** — 완료 상태에서 폼으로 되돌아가는 UI는 제공되지 않는다(다시 하려면 화면 재진입 필요).

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 기본(요청) | 최초 진입 | 로고 + 안내 문구 + 이메일 폼 + 전송 버튼 + 로그인 링크 |
| 입력 검증 실패 | 빈 이메일로 제출 | API 호출 없이 "이메일을 입력해 주세요." 에러, 폼 유지 |
| 전송 중 | 요청 진행(`isPending`) | 버튼 비활성 + "전송 중..." |
| 미등록 이메일 | 응답 404 | "가입되지 않은 이메일입니다." 에러, 폼 유지 |
| 전송 실패(기타) | 404 외 에러 | "전송에 실패했어요. 잠시 후 다시 시도해 주세요." 에러, 폼 유지 |
| 완료(성공) | 응답 200 | 완료 문구 + "로그인으로 돌아가기" 버튼으로 카드 교체 |
| 로그인 상태 접근 | 토큰 보유 상태 진입 | 화면 미노출, `proxy.ts`가 `/`로 리다이렉트 |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 재설정 요청 | `POST /auth/password-reset/request` `{email}` (`requestPasswordReset`) | 폼 제출 시. 200=발송, 404=미등록. 응답에 토큰 미노출. |
| 재설정 메일 발송 | 백엔드 `BackgroundTasks` → `send_password_reset_email` → SMTP(mailer) | 요청 성공 시 서버가 비동기 발송. SMTP 미설정 시 발송 생략(요청은 성공). |
| 재설정 토큰 | 서버 발급, TTL 60분(3600초), `PasswordReset` 저장 | 메일 링크(`/reset-password?token=…`)로만 전달. 실제 재설정은 `/reset-password`에서 `confirmPasswordReset`. |
