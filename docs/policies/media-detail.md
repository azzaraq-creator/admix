# 매체 상세 화면 정책서 (UI중심)

> **이 문서는 "이 화면이 어떤 규칙으로 동작하는가"를 정의합니다.**
> 화면을 위→아래 **UI 블록 순서**로 읽습니다. 각 블록은 **"무엇 + 동작 규칙"**만 적고, 디자인(색·여백·컴포넌트 모양)은 Figma에 둡니다. 미정은 줄 안에 `❓`로 표시하고 맨 아래 "미정" 섹션에 한 번 더 모읍니다.

| | |
|---|---|
| **화면** | 매체 상세 · `/media/[id]` |
| **진입** | 고정매체(`/fixed`) 상세 드로어의 "자세히" · 매체 카드/링크에서 매체 상세 전체 화면으로 이동 ❓(정확한 진입점 미확인) |
| **Figma** | ❓(미확인) |
| **상태/작성자** | `draft` · (코드 기반 자동생성) · 2026-07-09 |
| **관련 화면** | 고정매체(`fixed.md`, 상세 드로어와 동일 컨텐츠 컴포넌트 재사용), 내 제안서 |

---

## 1. 목적
선택한 옥외광고 매체 한 건의 전체 정보(이미지·기본정보·주요 인구층·설명·상품 목록·규격·특징·유동인구 데이터)를 한 화면에서 보여 주고, "매체 담기"로 제안서 작성 흐름으로 이어 주는 화면이다.

- 핵심 사용자: 옥외광고 매체를 검토하는 광고주/마케터
- 성공 기준: ❓ (예: 상세 → 매체 담기 전환율 — 미정)

## 2. 권한
- 접근 권한은 **전체 사용자**(비회원 포함). `(client)/(main)` 레이아웃에 별도 인증 가드가 없어 로그인 없이 열람 가능하다.
- **매체 담기**는 로그인 없이도 가능하다. 제안서 API가 회원 토큰 대신 **세션 ID(`session_id`)** 로 동작하기 때문(`proposalsClientApi`가 모든 호출에 `getSessionId()` 첨부).
- 제안서 생성/담기에는 **사용자 등급별 한도**가 존재한다(응답 `ProposalLimitDetail`: `reason: "limit_reached"`, `tier: guest | member | verified`, `limit`). 이 화면은 그 한도를 소비하는 진입점이지만, **구체 수치와 한도 도달 시 화면 처리는 이 화면 코드에 없음** → ❓(제안서 도메인 정책 참조 필요).

## 3. UI 블록 (위 → 아래)

데이터는 `useMediaDetail(id)` → `GET /media/{id}`(`MediaDetail`) 한 번으로 채운다. **응답 도착 전(`detail` 없음)에는 화면이 아무것도 렌더하지 않는다**(`MediaDetailView`가 `null` 반환 — 별도 로딩/스켈레톤 없음).

### 3.0 이미지 영역
- **기능**: 매체 대표 이미지 1장.
- **규칙**:
  - 표시 우선순위 **`thumbnailUrl` → `imageUrls[0]`**. 둘 다 없으면 회색 플레이스홀더만 노출(빈 박스).
  - 이미지는 영역을 `object-cover`로 채운다. **여러 장 갤러리/스와이프·클릭 확대는 없음**(현재 단일 이미지만).

### 3.1 헤더 (뱃지 · 매체명 · 가격 · 매체 담기)
- **기능**: 매체 식별 정보와 담기 진입.
- **규칙**:
  - **뱃지**: `badge` 값이 `popular`이면 "인기", `new`이면 "신규", `null`이면 미표시. (백엔드 기준: `is_popular_yn` 우선, 없으면 `is_newly_built_yn` → `new`.)
  - **매체명**: `name`(백엔드에서 `name + second_name` 결합, 없으면 `-`).
  - **가격**: `minAdvertisementFeeKrw`를 `formatFee`로 변환 → "최소집행금액 N만원"(원화를 만원 단위로 반올림). 값이 `null`이면 **"최소집행금액 협의"**.
  - **매체 담기 버튼**:
    - 클릭 시 `AddToProposalModal`(제안서에 매체 추가 모달) 오픈.
    - `mediaId`가 없으면 **비활성(disabled)**. (상세 화면 진입 시엔 항상 존재하므로 사실상 항상 활성.)

### 3.2 주요 지표 밴드 (월평균 유동인구 수 · 주요 인구층)
- **기능**: 유동인구 요약 2지표.
- **규칙**:
  - **유동인구 데이터(`population`)가 있을 때만 노출**. 없으면 밴드 전체 숨김.
  - **월평균 유동인구 수**: `monthlyFootTraffic`을 천단위 콤마로 표시.
  - **주요 인구층**: `malePct ≥ femalePct`면 "남성", 아니면 "여성" + 연령 비율 중 `value` 최댓값 구간의 라벨(예: "30대")을 이어 표시.

### 3.3 매체 설명
- **기능**: 매체 소개 문단.
- **규칙**:
  - `description` 표시. **기본 3줄 클램프(`line-clamp-3`)**.
  - 하단 "매체 설명 더보기/접기" 토글로 전체 펼침 ↔ 3줄 축소. (chevron 회전으로 상태 표시.)
  - `description`이 `null`이면 컴포넌트 기본 문구(맥스비전 예시)가 들어감 ❓ — 실데이터 없을 때 문단 처리(빈 값/숨김 여부) 확인 필요.

### 3.4 매체 목록 (상품 플랜 선택)
- **기능**: 이 매체의 개별 상품(플랜) 목록 + 단일 선택.
- **규칙**:
  - `plans` 배열로 카드 그리드 렌더(제목 `title` = 상품표시명, 부제 `subtitle` = "N기 N면 / N초 / 계약기간" 조합). 백엔드에서 **`product_master_type == "PM_INDIVIDUAL"` 플랜만** 내려옴.
  - `plans`가 **0건이면 "매체 목록" 섹션 전체 숨김**.
  - 라디오형 **단일 선택**(기본 첫 번째 index 0 선택). 선택된 플랜의 `planNo`는 매체 담기 시 `AddToProposalModal`에 전달돼 제안서 아이템의 `plans` 매핑으로 저장된다.

### 3.5 규격
- **기능**: 사이즈/규격 표시.
- **규칙**: `sizeText`(백엔드 `media_shape_summary`)가 있을 때만 노출, 없으면 섹션 숨김.

### 3.6 특징
- **기능**: 매체 속성 목록(라벨-값 쌍).
- **규칙**:
  - `features` 배열을 그대로 나열. 각 항목은 `label`/`value`.
  - 백엔드에서 **값이 없거나 `-`, 빈 문자열인 항목은 애초에 제외**하고 내려줌(예: 매체 카테고리, 타입, 노출 종류, 판매 형태, 고정/이동, 기기 수량, 리드타임 등 — 존재하는 것만).
  - `features`가 비어도 섹션 컨테이너 자체는 항상 렌더됨(조건부 숨김 없음).

### 3.7 유동 인구 데이터 (성별 도넛 · 연령대 막대)
- **기능**: 유동인구 상세 차트.
- **규칙**:
  - **`population`이 있을 때만 노출**(없으면 섹션 숨김).
  - **성별 비율**: `malePct`/`femalePct` 도넛(`GenderDonut`).
  - **연령대 비율**: `ageRatios` 막대(`AgeBarChart`, 최대 막대 높이 240). 각 구간 라벨과 `bound`(`under`/`over`, 예: "10대 이하", "60대 이상")로 표기.
  - 유동인구 출처: 백엔드가 매체의 `source_detail_id` → 인접 상권(sangwon)을 거리 기준(`SANGWON_MAX_DISTANCE_M`) 이내로 매칭. 매칭 실패·거리 초과·유동량 0이면 `population = null` → 3.2/3.7 모두 숨김.

### 3.8 매체 담기 모달 (`AddToProposalModal`)
- **기능**: 이 매체를 하나 이상의 "작성중" 제안서에 담기.
- **규칙**:
  - **표시 대상 제안서**: 내 제안서(`useMyProposals`) 중 **작성중만**. `contracted`(계약완료)·`custom`(맞춤제안)·`execution_requested`(집행요청)는 제외.
  - **새 제안서 만들기**: 이름 입력 → 생성. 생성 즉시 선택 목록에 자동 체크. 이름 공백이면 생성 버튼 비활성, 중복 클릭(연타) 방지.
  - **중복 방지**: 이미 이 매체(`mediaId`)를 담고 있는 제안서는 "이미 추가됨"으로 표시 + 선택 불가(disabled).
  - **선택 후 추가**: 선택된 제안서들에 대해 `addItems`(`POST /proposals/{id}/items`)를 **병렬 호출**, 선택한 플랜(`planNo`)을 `plans` 매핑으로 함께 전송. 성공 시 모달 닫힘.
  - 선택 0건이면 하단 "선택한 제안서에 추가하기" 버튼 비활성.
  - 보유 작성중 제안서 0건이면 빈 상태(아이콘 + "보유한 제안서가 없습니다") 표시.
  - 한도 도달(`limit_reached`) 시 이 모달에서의 처리(생성/담기 차단·안내) ❓ — 이 화면 코드엔 분기 없음.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 로딩/미도착 | `useMediaDetail` 응답 전 | **아무것도 렌더 안 함**(`null`). 스켈레톤·스피너 없음 ❓ |
| 성공(result) | `detail` 도착 | 전 블록 렌더(있는 데이터만) |
| 유동인구 없음 | `population == null` | 3.2 지표 밴드 + 3.7 차트 섹션 숨김 |
| 이미지 없음 | `thumbnailUrl`/`imageUrls` 모두 없음 | 이미지 영역이 회색 플레이스홀더 |
| 매체 없음(404) | `GET /media/{id}` 404 | 백엔드는 404 반환. 프런트는 `detail` 미도착과 동일하게 `null` 렌더(전용 404 화면 없음) ❓ |
| 에러 | 조회 실패 | 전용 처리 없음 → `null` ❓ |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 매체 상세 전체 | `GET /media/{id}` (`MediaDetail`) | 진입 시 `useMediaDetail(id)` 1회, `staleTime` 60초 |
| 이미지 | `thumbnailUrl` / `imageUrls[]` | 상세 응답에 포함 |
| 상품 플랜 | `plans[]` (`PM_INDIVIDUAL`만) | 상세 응답에 포함 |
| 유동인구 | `population` (상권 `sangwon_population` 조인) | 상세 응답에 포함, 거리 매칭 실패 시 `null` |
| 내 제안서 목록 | `useMyProposals` → `GET /proposals?session_id=` | 매체 담기 모달 오픈 시 |
| 제안서 생성 | `POST /proposals` | 모달 "새 제안서 만들기" |
| 제안서에 매체 추가 | `POST /proposals/{id}/items` | 모달 "추가하기"(선택 제안서마다 병렬) |
