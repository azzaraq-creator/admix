## 1. 목적
관리자(admin) 계정을 등록·조회·수정·삭제하고, 일반 관리자의 **메뉴별 접근 권한**을 지정하는 화면이다. 마스터 계정이 조직 내 관리자 인원과 그들이 볼 수 있는 메뉴를 통제한다.

- 핵심 사용자: 마스터 계정 관리자
- 성공 기준: ❓

## 2. 권한

접근·권한 정책의 상세 근거는 [관리자 인증·권한 정책](admin-auth-permissions.md) §2·§3에 있다. 이 화면 기준 요약:

**전 엔드포인트(조회 포함)가 `account` 권한 관리자 전용**이다(2026-07-27 변경, 커밋 `ec89551` 다음). 마스터는 권한 무관 전체 허용.

| 사용자 | 목록/상세 조회 | 생성/수정/삭제 | 계정 관리 메뉴 노출 |
|---|---|---|---|
| 마스터 계정(`account_type == "마스터 계정"`) | 가능 | 가능(마스터 대상 포함) | 노출 |
| `account` 권한 보유 관리자 | 가능(`require_permission("account")`) | 가능 — **단 마스터 티어는 봉인** | 노출 |
| `account` 권한 없는 관리자 | **403** | **403** | 미노출 |

- **마스터 티어 봉인**(`_guard_master_tier`, 권한 상승 방지): `account` 권한만 가진 비마스터는 ① 마스터 계정 **생성** ② 기존 계정을 마스터로 **승격**(자기 자신 포함) ③ 마스터 계정 **수정/삭제** 를 시도하면 403. 비마스터끼리의 권한 부여·비밀번호 변경은 "계정 관리" 범위로 허용된다.
- **마지막 마스터 보호**: 활성 마스터가 자기 하나뿐이면 그 계정의 삭제·강등(계정 유형 변경)·비활성화를 백엔드가 400으로 차단한다(§5·서비스 `_other_active_masters`).
- 이중 방어: 프론트 LNB 게이팅(UX) + 백엔드 `require_permission` + 마스터 봉인 가드. 실제 방어선은 백엔드.

## 3. UI

### 3.0 목록 화면 헤더 (`/admin/roles`)
- **기능**: 화면 제목 "계정 관리".
- **규칙**: 정적 텍스트.

### 3.1 목록 상단바 (총건수 · 액션)
- **기능**: 검색 결과 총건수와 우측 액션 버튼(`엑셀 다운로드`, `계정 생성`).
- **규칙**:
  - 총건수 = 검색/필터 적용 후 행 수.
  - `계정 생성` 클릭 → `/admin/roles/create` 이동.
  - `엑셀 다운로드` 버튼은 현재 **핸들러 미연결(no-op)** ❓.

### 3.2 검색 필터
- **기능**: 목록을 클라이언트에서 필터링. (전체 목록을 받아온 뒤 프론트에서 거른다)
- **규칙**:
  - 필터 항목: `기간(dateRange)` · `계정 유형(select: 마스터 계정/관리자 계정)` · `상태(select: 활성/비활성)` · `검색어 대상(select: 이름/이메일(ID))` + `검색어(text)`.
  - 실제 적용되는 필터는 **계정 유형·상태·검색어(이름 또는 이메일 부분일치)**. 검색어는 이름·이메일 양쪽에 대해 부분일치로 걸린다.
  - `기간` 필터와 `검색어 대상` select는 UI에 존재하나 현재 필터 로직에 반영되지 않는다 ❓.

### 3.3 목록 표 (CommonTable)
- **기능**: 관리자 계정 목록.
- **규칙**:
  - 컬럼: `No` · `이름` · `이메일(ID)` · `계정 유형` · `부서/역할` · `상태` · `생성일`.
  - `No`는 필터 후 순번(1부터), 실제 식별자는 계정 UUID(`no` 필드).
  - 정렬: 백엔드가 **생성일 내림차순**으로 반환.
  - 상태 표시: 백엔드 `active`/`disabled` → 화면 `활성`/`비활성`으로 변환.
  - 빈 값은 `-`로 표시(이름/유형/부서).
  - **행 클릭** → `/admin/roles/{id}` 상세 이동.
  - 페이지당 10개, 페이지 크기 select 사용.

### 3.4 생성/상세 폼 헤더
- **기능**: 폼 제목.
- **규칙**: 생성은 "계정 생성", 상세(수정)는 "계정 상세". 상세는 계정 조회 전까지 "불러오는 중..." 표시.

### 3.5 계정 정보 입력 필드 (2열 그리드)
- **기능**: 계정 속성 입력.
- **규칙**:
  - **계정 유형** (필수): select `마스터 계정` / `관리자 계정`. 선택값에 따라 3.7 권한 설정 박스 노출이 결정된다.
  - **이름** (필수): 텍스트.
  - **이메일(ID)** (필수): 텍스트. **수정 모드에서는 disabled**(변경 불가). 서버는 생성 시 이메일 중복이면 409.
  - **비밀번호**: 생성 시 **필수·8자 이상**, 수정 시 **선택**(입력 시에만 변경, 8자 이상). 프론트에서 생성 시 8자 미만이면 저장 차단 alert.
  - **부서/역할**: 텍스트(선택). 빈 값은 `null` 전송.
  - **전화번호**: 텍스트(선택). 빈 값은 `null` 전송.
  - **상태** (수정 모드에만 노출): select `활성화`/`비활성화`. 생성 시에는 서버 기본 `active`.
  - **생성일** (수정 모드에만 노출): 읽기 전용, `YYYY-MM-DD` 표시.

### 3.6 필수값 검증
- **기능**: 저장 전 최소 입력 확인.
- **규칙**: `계정 유형` · `이름` · `이메일`이 비어 있으면 "계정 유형·이름·이메일은 필수입니다." alert 후 중단. 생성 모드에서 추가로 비밀번호 8자 미만이면 별도 alert 후 중단.

### 3.7 권한 설정 박스 (메뉴별 체크박스)
- **기능**: 일반 관리자에게 부여할 메뉴별 접근 권한을 토글.
- **규칙**:
  - **계정 유형이 "마스터 계정"이면 이 박스 전체가 숨김**(마스터는 전 메뉴 자동 허용이라 무의미).
  - 체크박스 6종(3열 그리드): `광고 매체 관리`(`media`) · `회원 관리`(`member`) · `AI 채팅 관리`(`chat`) · `비즈니스 관리`(`business`) · `FAQ 관리`(`faq`) · `계정 관리`(`account`).
  - 대시보드는 로그인 기본 페이지라 권한 대상에서 제외(체크박스 없음).
  - 각 라벨 → 백엔드 `menu_key` 매핑으로 전송. 서버는 허용 키 집합 밖이면 400.
  - 토글 시 해당 `menu_key`를 permissions 배열에 추가/제거.
  - `계정 관리(account)` 권한을 부여하면 해당 관리자에게 LNB "계정 관리" 메뉴가 노출되고 계정 CRUD가 가능해진다(2026-07-27부터). 단 마스터 티어 작업은 백엔드가 봉인한다(§2).
  - **선택 후속(비블로킹)**: 비마스터가 계정 유형 select에서 "마스터 계정"을 고를 수 있으나 저장 시 백엔드 403. UX상 옵션을 숨길지 미정 ❓.

### 3.8 하단 액션 버튼
- **기능**: 저장/삭제/목록 이동.
- **규칙**:
  - **목록** 버튼: `/admin/roles`로 이동.
  - **생성 모드**: `생성` 버튼 → 저장. 성공 시 "저장 완료" alert 후 목록으로 이동. 실패 시 서버 에러 메시지 alert.
  - **수정 모드**: `삭제` + `저장` 버튼.
    - `저장`: 변경 저장. 성공 alert(목록 이동 없음, 화면 유지). 마지막 마스터 강등/비활성화 시도 시 서버 400 → 실패 alert.
    - `삭제`: "삭제하시겠습니까?" confirm → 확인 시 삭제. 성공 시 alert 후 목록 이동. 마지막 마스터 삭제 시도 시 서버 400 → 실패 alert.
  - 저장 진행 중(`saving`)에는 저장/생성 버튼 disabled.

## 4. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 목록 결과 있음 | 계정 존재 | CommonTable 행 노출 |
| 목록 결과 없음 | 필터 결과 0건 | 표 빈 상태(CommonTable 기본) |
| 상세 로딩 | 상세 진입 후 조회 전 | "불러오는 중..." 텍스트 |
| 폼 검증 실패 | 필수값 누락 / 비번 8자 미만 | alert 후 저장 중단 |
| 저장/삭제 성공 | API 200/201/204 | 완료 alert (생성·삭제는 목록 이동, 수정은 유지) |
| 저장/삭제 실패 | API 4xx (409·400·403 등) | 서버 에러 메시지 alert |
| 마지막 마스터 보호 | 유일 활성 마스터 강등/비활성/삭제 | 서버 400 "마지막 마스터…" → 실패 alert |

## 5. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 계정 목록 | `GET /admin/accounts` (`require_permission("account")`) | 목록 진입 시. 생성일 내림차순, 필터는 클라이언트 |
| 계정 상세 | `GET /admin/accounts/{id}` (`require_permission("account")`) | 상세 진입 시 |
| 계정 엑셀 | `GET /admin/accounts/export` (`require_permission("account")`) | 핸들러 미연결 no-op ❓ |
| 계정 생성 | `POST /admin/accounts` (`require_permission("account")` + 마스터 봉인 가드) | 생성 저장. 이메일 중복 409 |
| 계정 수정 | `PATCH /admin/accounts/{id}` (`require_permission("account")` + 가드) | 수정 저장. 부분 업데이트(`exclude_unset`) |
| 계정 삭제 | `DELETE /admin/accounts/{id}` (`require_permission("account")` + 가드) | 삭제. 성공 204 |
| 권한(menu_key) | `admin_permission` 테이블 (1:N) | 생성/수정 시 permissions 배열 전량 교체. 유효 키: dashboard·media·member·business·faq·account·chat |

- 인증: `admin_token` 쿠키 → axios 인터셉터가 `/admin/*`에 자동 첨부([권한 정책](admin-auth-permissions.md) §1).
