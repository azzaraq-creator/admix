## 1. 화면 목적 (Why)

 계정으로 로그인해, 비회원 상태의 기능 제한(예: 채팅 토큰 5회)을 해제하고 사용자 등급에 맞는 권한을 부여한다.

- **핵심 가치**: 빠른 로그인으로 비회원 → 회원 기능을 막힘 없이 이어가게 한다.
- **주 사용자**: 기존 회원(재방문), 비회원(전환 직전).
- **성공 기준**: [미정 — 로그인 성공률, 소셜 로그인 비중 등]

---

## 2. 사용자 & 권한 정책

로그인 화면 자체는 모든 사용자에게 동일하게 보인다. 로그인 결과로 등급(개인/기업)이 결정되며, 등급별 권한은 각 기능 화면 정책서에서 정의한다.

| 사용자 구분 | 접근 | 비고 |
|---|---|---|
| 비회원 | 로그인 화면 접근 가능 | 로그인/소셜로그인/회원가입 진입 |
| 기존 회원 | 동일 | 로그인 후 등급별 권한 적용 |

> 로그인 후 등급 판정·토큰 한도 적용 규칙은 `ai-media-recommend.md` 2번 참조.

## 3. 핵심 기능 (What)

### 3.1 이메일/비밀번호 로그인

- **무엇을**: 이메일 + 비밀번호로 로그인.
- **동작 규칙**: [미정 — 입력 검증(이메일 형식, 빈 값), 성공 시 이동, 실패 시 처리]
- **제약**: [미정 — 로그인 버튼 활성 조건(둘 다 입력 시 활성?), 로그인 시도 횟수 제한?]

### 3.2 로그인 유지

- **무엇을**: 체크 시 세션을 길게 유지.
- **동작 규칙**: 체크 시 **30일 유지**, 미체크 시 **브라우저 세션 종료까지**(닫으면 만료).

### 3.3 아이디/비밀번호 찾기

- **무엇을**: 계정 복구로 이동.
- **동작 규칙**: [미정 — 아이디와 비밀번호 찾기가 한 화면인지 분리인지, 복구 수단(이메일/휴대폰 인증)]

### 3.4 소셜 로그인 (카카오 / 네이버)

- **무엇을**: 카카오톡·네이버 계정으로 로그인.
- **동작 규칙**: 최초 소셜 로그인 시 **자동 회원가입** 후 바로 로그인 완료(별도 추가입력 단계 없음). 같은 이메일의 일반계정이 있어도 **연동/병합하지 않고 별개 소셜 계정을 생성**한다(provider_id 로만 식별). [2026-07-27] 결정 — [social-account-separation](../plans/2026-07-27-social-account-separation.md).
- **제약**: 소셜 자동가입 사용자의 기본 등급은 [미정 — 개인회원 추정].

### 3.5 회원가입 이동

- **무엇을**: "회원가입" 링크로 가입 화면 진입.
- **동작 규칙**: [미정 — 별도 회원가입 화면 라우트]

### 3.6 닫기 (X)

- **무엇을**: 모달을 닫는다.
- **동작 규칙**: 닫으면 직전 화면으로 돌아가고 **진행 중이던 상태(입력한 대화/조건)는 보존**한다. 단 비회원 기능 제한은 유지(로그인 전까지 막힌 기능은 계속 막힘).

## 4. 사용자 플로우 (How)

```
로그인 모달 진입 ([트리거 미정])
 ├─ 이메일/비번 입력 → 로그인
 │     ├─ 성공  → 모달 진입이면 직전 화면 복귀 / `/login` 진입이면 홈
 │     └─ 실패  → [에러 처리·시도 제한 미정]
 ├─ 소셜 로그인(카카오/네이버)
 │     ├─ 기존 연동 계정 → 로그인 성공
 │     └─ 최초            → 자동 회원가입 → 로그인 성공
 ├─ 아이디/비밀번호 찾기  → [복구 화면 미정]
 ├─ 회원가입              → 회원가입 화면
 └─ 닫기(X)               → [복귀 위치 미정]
```

## 6. 비즈니스 규칙 / 정책

- "로그인 유지" 체크 시 세션 **30일**, 미체크 시 **브라우저 세션 종료까지**.
- 로그인 성공 후 이동: 모달 진입이면 **직전 화면 복귀**, `/login` 직접 진입이면 **홈**.
- 소셜 최초 로그인 시 **자동 회원가입**(추가 입력 없음). 기본 등급은 [미정].
- [미정 — 비밀번호 정책, 로그인 연속 실패 시 시도 제한/잠금]
- [미정 — 비회원 토큰 사용 이력의 로그인 후 이관 여부 (ai-media-recommend.md와 정합 필요)]

## 7. 예외 & 엣지 케이스

- 잘못된 이메일/비밀번호 → [에러 처리·시도 제한 미정]
- **제재 회원** 로그인 → 오늘이 **활성 제재 기간**(`start_date`~`end_date`, 종료 없음=무기한) 안이면 백엔드 403 "서비스 이용이 제한되었습니다." → 제한 안내 모달 표시. `status` 플래그가 아니라 **제재 날짜로 판정**(미래·종료 제재는 로그인 허용). 제재 관리: [admin-members](admin-members.md) §3.10.
- **탈퇴 회원** 로그인 → 403 "탈퇴한 계정입니다."
- 소셜 이메일이 기존 일반계정과 동일 → **연동/병합 안 함, 별개 소셜 계정 생성**(provider_id 로 식별). [social-account-separation](../plans/2026-07-27-social-account-separation.md).
- 로그인 유도 모달을 닫은 경우 → [진행 중이던 작업 보존 여부 미정]
- 이미 로그인된 상태에서 모달 진입 → [처리 미정]
- 소셜 인증 취소/실패 → [미정]
