## 1. 목적
고객이 접수한 문의를 관리자가 목록에서 확인하고, 상세로 들어가 답변을 작성·완료 처리하는 화면이다. 목록(검색·필터)과 상세(문의 내용 열람 + 답변 작성)를 한 흐름으로 다룬다.

- 핵심 사용자: `business` 권한을 가진 관리자(또는 마스터)
- 성공 기준: ❓

## 2. 권한
문의 관리 라우터(`/admin/inquiries`)는 **`require_permission("business")`** 로 보호된다(`backend/src/routers/inquiries.py`). 즉 목록 조회·상세 조회·답변(PATCH) 모두 `business` 메뉴 권한이 필요하다. 마스터 계정은 권한 설정과 무관하게 전체 허용, 권한 없는 일반 관리자는 API 직접 호출 시 403. (권한 모델 상세: [admin-auth-permissions.md](admin-auth-permissions.md) §3 — 제안서 관리와 동일한 `business` 키를 공유)

| 사용자 | 접근 | 비고 |
|---|---|---|
| 마스터 계정 | 목록·상세·답변 전체 | 권한 설정 무관 |
| `business` 권한 관리자 | 목록·상세·답변 전체 | |
| 권한 없는 관리자 | 접근 불가 | 프론트 사이드바 미노출 + API 403 |

## 3. UI 블록

### 3.0 목록 — 페이지 헤더
- **기능**: 화면 제목 표시.
- **규칙**: `문의 관리` 텍스트 고정 노출.

### 3.1 목록 — 검색/필터 바
- **기능**: 목록을 기간·상태·키워드로 좁힌다. (`inquirySearchOptionList`)
- **규칙**:
  - **기간(period)**: `dateRange` 타입 필터가 UI에 노출된다. **단, 현재 목록 필터링 로직(`InquiriesListView`의 `filtered`)은 상태·키워드만 적용하고 기간 값은 사용하지 않는다** → 기간을 골라도 목록이 좁혀지지 않음. `❓`(기간 필터 실동작 미구현)
  - **상태(status)**: `select`. 옵션 `답변 대기` / `답변 완료`. 선택 시 해당 상태 행만 노출.
  - **키워드(keyword)**: `text` 입력. **제목(title) 또는 이름(name)에 포함**되면 통과(부분 일치, 대소문자 구분). 내용(content)·이메일 등은 검색 대상 아님.
  - 모든 필터링은 **클라이언트 측**에서 이미 받아온 목록에 대해 수행(서버 재조회 없음). 서버 목록 API(`GET /admin/inquiries`)는 파라미터 없이 전체를 최신순으로 반환.

### 3.2 목록 — 상단바 (총건수 · 액션)
- **기능**: 총 건수 표시 + 우측 액션 버튼.
- **규칙**:
  - 총건수 = 필터 적용 후 행 수(`filtered.length`).
  - 우측: **엑셀 다운로드 버튼** 노출. **현재 `onClick` 핸들러가 연결돼 있지 않아 클릭해도 동작하지 않는다.** `❓`(엑셀 다운로드 사양·구현)
  - 페이지당 10개씩 보기 select 내장(`usePageSizeSelect`, `pageSize=10`).

### 3.3 목록 — 표 (`CommonTable`)
- **기능**: 문의 목록을 컬럼 표로 노출. (`inquiryColumnList`)
- **규칙**:
  - 컬럼: **No**(필터 후 순번 1부터, 서버 값 아님) · **이름** · **제목** · **문의 내용**(최대 폭 360px 넘으면 말줄임) · **상태**(뱃지) · **제출일**(`YYYY-MM-DD`).
  - 상태 뱃지: `답변 대기` / `답변 완료` 2종(`InquiryStatusBadge`). 백엔드 원본값 `pending`/`answered`를 서비스에서 한글 라벨로 매핑(`_STATUS`).
  - **행 클릭 시 상세로 이동**: `/admin/inquiries/{id}`.
  - 정렬: 서버가 `created_at` 내림차순(최신순)으로 고정 반환. 컬럼 클릭 정렬 없음.
  - 페이지네이션: 10개 초과 시 페이지 분할(shadcn 페이지네이션).

### 3.4 상세 — 로딩
- **기능**: 상세 데이터 로딩 중 표시.
- **규칙**: `useInquiry(id)` 응답 전에는 `불러오는 중...` 텍스트만 노출. (에러 전용 화면 없음 `❓`)

### 3.5 상세 — 문의 상세 카드
- **기능**: 접수된 문의 정보를 읽기 전용으로 표시.
- **규칙**:
  - 필드(2열 그리드): **문의자**(이름, 없으면 `-`) · **이메일**(없으면 `-`) · **전화번호**(없으면 `-`) · **회사**(없으면 `-`) · **제출일**(`YYYY-MM-DD`) · **문의 상태**(뱃지).
  - 전체 폭: **문의 제목**, **문의 내용**(줄바꿈 유지 `whitespace-pre-line`).
  - 모두 표시 전용(편집 불가).

### 3.6 상세 — 답변 정보 카드
- **기능**: 답변자·답변 일시 표시 + 답변 작성/열람.
- **규칙**:
  - **답변자**: `answerer`(없으면 `-`). 답변 시점의 **관리자 이름을 스냅샷 저장**(`answered_by_name`, `answer_inquiry`에서 `admin.name` 기록) → 이후 관리자 계정명이 바뀌어도 답변 당시 이름 유지. (스냅샷이 비어 있고 `answered_by`만 있으면 Admin 테이블에서 이름 재조회하는 폴백 존재)
  - **답변 일시**: `answeredAt`의 앞 10자(`YYYY-MM-DD`)만 표시, 없으면 `-`.
  - **답변 입력(textarea)**: 초기값은 기존 답변(`inquiry.answer`). 높이 고정(약 160px), 크기 조절 불가.
  - **읽기 전용 전환**: 상태가 `답변 완료`면 textarea `readOnly`, 하단 `답변 완료 처리` 버튼 미노출 → **답변 완료 건은 재수정 불가**.
  - **목록으로 버튼**: `/admin/inquiries`로 이동.
  - **답변 완료 처리 버튼**(답변 대기 상태에서만 노출):
    - 답변이 공백이면 `입력 확인` 알림 후 중단(빈 답변 전송 불가). 서버도 `answer` `min_length=1` 검증.
    - `답변 완료 처리를 하시겠습니까?`(전송/취소) 확인 → `PATCH /admin/inquiries/{id}/answer` 호출.
    - 성공 시 `답변 처리 완료` 알림. 실패 시 서버 에러 메시지 알림(`extractApiError`).
    - 전송 처리 중(`isPending`) 버튼 비활성화.

## 4. 상태 전이 (문의 상태)

| 전이 | 트리거 | 서버 처리 |
|---|---|---|
| `답변 대기`(pending) → `답변 완료`(answered) | 답변 완료 처리 | `answer` 저장, `status="answered"`, `answered_by`/`answered_by_name`(스냅샷)/`answered_at`(UTC now) 기록 |
| 완료 → 대기 | 없음 | 되돌리는 경로 없음(단방향). 완료 후 수정 불가 |

> 문의 생성(`pending`)은 고객 측 회원 접수(`POST /inquiries`, `create_inquiry`)에서 발생. 관리자 화면에서 문의를 새로 만들거나 삭제하는 기능은 없다.

## 5. 화면 상태

| 상태 | 발생 조건 | 노출 / 동작 |
|---|---|---|
| 목록 로딩 | 목록 조회 중 | ❓(전용 로딩 UI 미확인) |
| 목록 성공 | 데이터 있음 | 표 + 페이지네이션 |
| 목록 결과 없음 | 필터 0건 | ❓(빈 상태 문구 — `CommonTable` 기본 동작에 위임) |
| 상세 로딩 | 상세 조회 중 | `불러오는 중...` 텍스트 |
| 상세 성공 | 데이터 있음 | 문의 상세 + 답변 정보 카드 |
| 상세 없음(404) | 잘못된/없는 id | 서버 404(`문의를 찾을 수 없습니다.`), 프론트 전용 화면 `❓` |
| 답변 처리 실패 | PATCH 에러 | 서버 에러 메시지 알림 |

## 6. 데이터 & 연동

| 항목 | 출처 / 연동 | 트리거 · 비고 |
|---|---|---|
| 문의 목록 | `GET /admin/inquiries` (`inquiriesApi.list`) | 화면 진입 시. 파라미터 없음, 전체 최신순 |
| 문의 상세 | `GET /admin/inquiries/{id}` (`inquiriesApi.get`) | 상세 진입 시 |
| 답변 저장 | `PATCH /admin/inquiries/{id}/answer` (`inquiriesApi.answer`) | 답변 완료 처리. 성공 시 목록·상세 쿼리 무효화 |
| 상태 라벨 | 서버 매핑 `_STATUS` | `pending→답변 대기`, `answered→답변 완료` |

> 프론트 필터·검색·엑셀은 서버 연동 없이 클라이언트에서 처리(엑셀은 현재 미연결).

## 7. 미정 (Open Questions / 결정 로그)
