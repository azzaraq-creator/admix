## #4 · fixed 지도 — 채팅 패널 접기 시 지도가 빈 영역을 채우지 못함

- **지적**: fixed 페이지에서 "채팅 패널 접기"(`aria-label="채팅 패널 접기"`, `chatOpen=false`)로 좌측 패널을 접으면, 지도가 넓어진 영역을 채우지 못하고 회색으로 남음.
- **원인**: `useKakaoMap.ts`의 ResizeObserver가 `map.relayout()`을 **`becameVisible`(이전 크기 0→양수, 숨김→표시)일 때만** 호출. 패널 접기/펼치기는 지도 컨테이너 너비가 `left-[384px] ↔ left-0`로 바뀌는 **일반 리사이즈**(두 차원 모두 0 아님)라 relayout이 누락됨. 카카오 지도는 컨테이너 크기 변경 시 `relayout()`을 호출해야 타일을 다시 그린다.
- **수정**: `useKakaoMap.ts` ResizeObserver — 크기가 바뀌면(`sizeChanged`, 양수 유지) 항상 `map.relayout()` 호출. 재센터링/`fitToMarkers`는 기존대로 `becameVisible`(모바일 숨김→표시)에만 실행. `relayout()`은 중심·줌을 보존하므로 패널 토글 시 지도가 튀지 않음. `width/height===0`이면 조기 반환(값만 기록).
- **검증**: `tsc --noEmit` exit 0, eslint exit 0. (브라우저 통합 동작이라 단위테스트 미작성 — 아래 메모 참조.)

## #5 · fixed 검색 — 주소 지오코딩 실패 시 "결과없음"이 안 뜸

- **지적**: `강남역 역삼로 10길 6`처럼 존재하지 않는 주소로 검색하면(카카오 keywordSearch·addressSearch 모두 `documents: []`, `total_count: 0`), 직전 bbox 기준 **기본 리스트가 그대로 표시**되고 "결과없음" 화면이 안 나옴.
- **원인**: fixed 검색바는 매체를 직접 검색하는 게 아니라 **지도 위치를 옮기는** 입력이다. 리스트는 검색어가 아니라 지도 bbox로 조회(`useFixedMediaInfinite`). `handleSearchSubmit`이 `geocodeAddress()` 실패(`null`) 시 `if (center) onRequestMapMove(...)`로 **아무 동작도 안 함** → 지도 안 움직임 → 리스트는 이전 영역 기본 목록 유지. 빈 상태 분기는 `searchResults.length === 0`만 봐서, 실제 결과가 있는 영역에선 절대 안 뜸.
- **수정**: `MediaSearchPanel.tsx` — `searchNotFound` 상태 신설. `handleSearchSubmit`에서 지오코딩 성공 시 `false`, 실패 시 `true`, 빈 입력이면 `false`로만 결정. 렌더 분기를 `searchNotFound || (!isLoading && searchResults.length === 0)`으로 확장해 `MediaEmptyResults` 표시.
  - **리셋 시점**: onChange(재입력)·필터 변경으로는 리셋하지 않고 **다음 검색 제출 때만** 갱신. onChange 리셋을 넣으면 재시도로 한 글자 입력하는 순간 기본 리스트가 깜빡여 되돌아옴 → "직전 위치 검색이 결과 없음" 의미가 깨짐.
  - **지도는 그대로**: 지오코딩 실패 시 지도는 이동 안 했으므로 이전 영역 마커를 유지(사용자 결정). 리스트만 결과없음 → 지도 핀/빈 리스트가 갈리지만, 리스트 버그만 요청이라 스코프 유지.
- **검증**: `tsc --noEmit` exit 0, eslint exit 0. 두 경로 모두 `MediaEmptyResults`로 수렴 확인 — (a) 유효 주소→빈 bbox(`searchResults.length===0`), (b) 무효 주소(`searchNotFound`).
- **커밋**: `fc32ae3`.

## #6 · 로그아웃 후 이전 사용자의 채팅 세션·제안서 잔존

- **지적**: 로그인 상태로 쓰다가 로그아웃했는데 ChatPanel에 로그인 때 채팅 세션이 남아 복원되고, 제안서 페이지에 이전 사용자의 제안서가 그대로 보임.
- **원인**: `handleLogout`(Sidebar·ProfileView 두 곳, **바이트 동일 복붙**)이 `clearUserToken()` + `queryClient.removeQueries({ authKeys.me })`만 수행. 두 가지를 안 지움:
  1. **localStorage `SESSION_KEY`("adRecommendV2.sessionId")** — 단일 key가 (a) 채팅 세션 복원(`useV2Chat`/`useReactChat` 마운트 시 이 id로 서버에서 메시지 복원)과 (b) 게스트 제안서 소유(`getSessionId()` → 제안서 list/create의 `session_id`) 양쪽에 쓰임. 로그아웃이 이 key를 안 지워 이전 세션이 복원됨.
  2. **React Query 캐시** — `me`만 제거하고 제안서 등 이전 토큰으로 캐시된 데이터를 안 비움.
  - 두 원인이 각각 독립적으로 필요: `clearSessionId`만으론 캐시에 남은 member 제안서가 안 지워지고, `queryClient.clear`만으론 localStorage·useState 기반 채팅이 안 지워짐(캐시 무효화는 localStorage/useState를 안 건드림).
- **수정**:
  - `lib/session.ts` — `clearSessionId()` 추가(get/set과 대칭).
  - `hooks/auth/mutations.ts` — **`useLogout()` 훅 신설**(queryClient+router 필요 → 훅). refresh 토큰 폐기(best-effort) → `clearUserToken()` + `clearSessionId()` + `queryClient.clear()` + `router.push("/")`. 두 핸들러의 복붙을 단일 훅으로 통합(#3와 동일한 drift 방지 — 한쪽만 고치고 다른 쪽 누락되는 것 방지).
  - `Sidebar.tsx`·`ProfileView.tsx` — handleLogout을 `useLogout()` 호출로 교체, 내 변경으로 고아가 된 import 정리(Sidebar: `useQueryClient`/`useRouter`/`authApi`/`authKeys`/`clearUserToken`/`getRefreshToken` + `router`/`queryClient` 지역변수 제거. ProfileView: `authApi`/`getRefreshToken`만 제거 — 나머지는 `handleWithdraw`가 계속 사용).
- **저장소 전수 확인**: 사용자범위 클라이언트 저장소는 **`SESSION_KEY` + 인증 쿠키뿐**. `useLnb.ts`의 LNB 펼침 상태는 UI 설정(사용자 무관)이라 유지. `queryClient.clear()`가 React Query 전 캐시 커버.
- **검증**: `tsc --noEmit` exit 0, eslint exit 0. **브라우저 미검증(수동 확인 필요)**: 로그인 → 제안서 1개 생성 + 채팅 전송 → 로그아웃 → `/fixed`·`/proposals` 재방문 시 둘 다 비어야 함. (채팅은 ChatPanel 재마운트 시에만 리셋되므로 `router.push("/")`가 `/fixed`를 언마운트하는지 확인 — 다른 라우트 세그먼트라 언마운트됨.)
- **스코프 밖(별도 판단 필요)**:
  - **로그인 시 게스트→member 마이그레이션**(반대 방향)은 이 수정 범위 밖. 이번 건은 로그아웃만 커버.
  - **`handleWithdraw`(ProfileView)** 도 동일 패턴(`clearUserToken` + `removeQueries({me})`만)이라 탈퇴 후 같은 세션 잔존 가능성. 이번엔 로그아웃만 요청이라 미변경 — 필요 시 동일하게 `useLogout` 흐름 재사용 가능.

## #9 · 탈퇴 회원 로그인 시 제재 모달 노출 → 탈퇴 hard delete 전환

- **지적**: 탈퇴한 회원이 로그인하면 "제재 관리에서 제재당한 계정"과 동일한 모달이 뜸.
- **원인**: (1) 탈퇴가 soft delete(`users.status="withdrawn"`)라 레코드가 남아 로그인 시 403 "탈퇴한 계정입니다"를 반환. (2) 프런트 `LoginModal.tsx:116`이 **403이면 detail 무관하게 제재 모달**(`setRestrictedOpen`)을 띄움 → 탈퇴(403)도 제재 모달로.
- **수정 방향(사용자 결정)**: 개인정보처리방침 "탈퇴 즉시 파기"에 맞춰 **hard delete**로 전환. 제안서는 CASCADE 삭제 대신 제출 당시 신청자 스냅샷(회원유형·회사명·이름·이메일·전화)으로 보존. 소셜 재로그인 복구 제거. 작성중(new) 제안서는 함께 삭제.
- **수정**: 상세 설계·배포 순서·컴플라이언스 게이트는 [account-withdrawal-hard-delete](../plans/2026-07-23-account-withdrawal-hard-delete.md) 참조. 요약:
  - proposal 스냅샷 5컬럼 + member_id FK CASCADE→SET NULL, `User.proposals` relationship `passive_deletes=True`(ORM delete-orphan 함정 회피), Alembic 036(+백필).
  - `withdraw()` hard delete, oauth `_reactivate_if_withdrawn` 제거, 기존 withdrawn 삭제 스크립트(`scripts/delete_withdrawn_accounts.py`).
  - 로그인 가드(`auth_service:109-110`, `deps.py:37-38`)는 유지(기존 withdrawn 삭제 전 안전망). **프런트 수정 불필요**(탈퇴=401 → 제재만 403 → 모달 정상).
- **검증**: `backend/tests/test_account_withdrawal.py` 5 케이스 통과, 백엔드 97 passed(회귀 없음). **운영 미배포**(배포 게이트: 백업 → 036 → 기존 withdrawn 삭제 → 코드). **프런트 브라우저 미검증.**
