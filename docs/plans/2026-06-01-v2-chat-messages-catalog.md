## 0. 상태 분류 체계

응답은 크게 **4가지 백엔드 `type`** + **프론트 자체 UI 문구**로 나뉜다.

| type | 의미 | UI 처리 |
|---|---|---|
| `chat` | 단순 안내 (검색 결과 없음 / 조건 변경 안내) | 메시지만 표시 |
| `need_more` | 슬롯 부족 (0~1개) | 메시지 + 매칭된 조건 칩 |
| `list` | 매체 추천 결과 (슬롯 ≥ 2) | 메시지 + 매체 리스트 |
| `confirmation_required` | 슬롯 충돌 → 예/아니오 확인 | 경고 박스 + 변경 diff + 빠른답 버튼 |

> 슬롯 6축: `ind`(업종), `prd`(제품), `obj`(목적), `tgt`(타깃), `loc`(지역), `cat`(카테고리) + `budget`(예산, 스칼라)
> 슬롯 수 카운트: 리스트 카테고리가 비어있지 않은 개수 + budget이 int면 +1

## 2. 백엔드 SSE 응답 — 일반 발화 (`POST /recommend/v2/stream`)

### 2.1 분기 흐름

```
사용자 발화
  ├─ pending_change 존재? (직전 턴에서 충돌 발생)
  │   ├─ 발화 = 긍정 (예/네/y/ok…)   → [B2] 교체 안내 + list
  │   ├─ 발화 = 부정 (아니오/no/취소…) → [B3] 유지 안내
  │   └─ 그 외 → pending 폐기, 새 발화로 처리 (안내 없음)
  ├─ 키워드 추출 (LLM)
  ├─ 기존 슬롯과 충돌? → [B1] confirmation_required
  ├─ 슬롯 0개   → [B4] need_more (0개)
  ├─ 슬롯 1개   → [B5] need_more (1개)
  ├─ 슬롯 ≥ 2, total = 0 → [B7] 결과 없음
  └─ 슬롯 ≥ 2, total > 0 → [B6] list
```

### 2.2 문구 표

| ID | type | 트리거 | 문구 | 출처 |
|---|---|---|---|---|
| **B1** | `confirmation_required` | 기존 슬롯에 다른 값의 새 코드 진입 (`_detect_conflicts`) | `기존에 설정된 조건과 충돌하는 항목이 있어요. 교체할까요? (예/아니오)`<br>`  · {카테고리}: {old} → {new}` | `recommend_v2.py:766-769` |
| **B2** | `chat` + 이어서 `list` | pending 상태에서 yes (`_is_yes`) | (1) `조건을 교체했어요:`<br>`  · {카테고리}: {old} → {new}`<br>(2) 이어서 B6 list 메시지 | `recommend_v2.py:703` |
| **B3** | `chat` | pending 상태에서 no (`_is_no`) | `기존 조건을 유지할게요. 추가 조건을 알려주세요 😊` | `recommend_v2.py:726` |
| **B4** | `need_more` | 슬롯 0개 (추출 실패 / 사전 미매칭) | `어떤 광고를 원하시는지 조금 더 구체적으로 알려주세요. 지역, 제품, 카테고리, 타깃 등이 도움이 됩니다 😊` | `recommend_v2.py:806-808` |
| **B5** | `need_more` | 슬롯 정확히 1개 | `현재 조건: {요약}`<br>`조건을 1개 더 알려주시면 적합한 광고를 찾아드릴게요 😊` | `recommend_v2.py:811-814` |
| **B6a** | `list` | 슬롯 ≥ 2, `total > top_k` | `조건에 맞는 매체를 {total}개 찾았어요. {shown}개만 먼저 보여드릴게요 😊` | `_build_list_message` |
| **B6b** | `list` | 슬롯 ≥ 2, `total ≤ top_k` | `조건에 맞는 매체를 {total}개 찾았어요.` | `_build_list_message` |
| **B7** | `list` | 슬롯 ≥ 2, `total = 0` | `조건에 맞는 매체를 찾지 못했어요. 조건을 조금 다르게 알려주시면 다시 찾아드릴게요 😊` | `recommend_v2.py:571-574` |
| **B8** | `error` | 예외 발생 (SSE `event: error`) | `{예외 메시지}` | `recommend_v2.py:844` |

### 2.3 yes/no 패턴 (B2/B3 트리거)

**yes 패턴**: `y(es)`, `네`, `예`, `응`, `그래`, `맞아`, `ok`, `오케이`, `좋아`, `변경(해)`, `바꿔(줘)`, `교체`
**no 패턴**: `n(o)`, `아니(요/다)`, `싫어`, `취소`, `안 해`, `그대로`, `유지`

### 2.4 요약 포맷 (`_format_slot_summary`)

```
업종: 화장품 / 지역: 강남 / 예산: 5,000만원 이하
```

- 카테고리는 사전 description으로 출력
- budget만 "**이하**" 접미사 (상한값 의미)

## 5. 기획적 일관성 점검 포인트 (발견된 불일치)

코드 정독 중 발견된 톤·문법·표현의 불일치. 기획 정의 시 통일 여부 결정 필요.

| # | 항목 | 사례 | 제안 |
|---|---|---|---|
| 1 | **이모지 사용 일관성** | "😊"가 안내성 문구 대부분에 붙는데, B1·B2·R4에는 빠짐 | 사용자 액션 유도 문구에만 일관되게 부여 / 또는 일괄 제거 |
| 2 | **결과 0건 멘트 차이** | 스트림(B7) `찾지 못했어요` ↔ 비-스트림(L4) `찾기 어려워요` | 한쪽으로 통일 |
| 3 | **list 매체 개수 표현** | B6a `{shown}개**만** 먼저` ↔ L5 `{shown}개를 먼저` | 조사 통일 |
| 4 | **need_more 0개/1개 시작 어구** | 0개 `어떤 광고를 원하시는지...` / 1개 `현재 조건: ...` | 0개 케이스도 `현재 조건: (없음)` 패턴으로 통일 가능 |
| 5 | **"매체" / "광고" 혼용** | 본문 `매체를 찾았어요` ↔ 안내 `광고를 찾아드릴게요` | 도메인 용어 일관화 |
| 6 | **R0 가상 메시지 따옴표** | `"업종: 화장품" 조건 제거` — 한글 문장에 큰따옴표+콜론, 시각적 이질감 | 예: `업종 "화장품" 제거` 또는 칩 형태 표현 |
| 7 | **B1의 문구 중복** | 본문 `기존에 설정된 조건과 충돌...` + UI 헤더 `⚠️ 조건 변경 확인 필요` + 하단 바 `조건을 교체할까요?` → 같은 의미 3번 반복 | 본문은 변경 내용만, 안내는 UI 영역에 위임 |
| 8 | **budget 요약의 "이하" 표기** | 다른 슬롯은 `지역: 강남`인데 budget만 `예산: 5,000만원 이하` | 의도된 표기인지 확인 (상한 의미) |
| 9 | **chip 표시 통화 단위** | 슬롯바에서는 description만 표시, 본문 요약에서는 "이하" 부여 | 슬롯바에서도 budget만 "이하" 부여 검토 |
| 10 | **첫 진입 가이드 vs need_more** | F2 가이드는 6축 모두 언급(`지역, 예산, 제품, 업종, 목적, 타깃`) / B4·L2는 4개만(`지역, 제품, 카테고리, 타깃`) | 동일한 6축 안내로 통일 |

## 6. 기획에서 추가 정의가 필요한 누락 케이스

코드상 현재는 별도 안내가 없지만 발생 가능하거나 UX 개선 여지가 있는 케이스.

| # | 케이스 | 현재 동작 | 검토 필요 사항 |
|---|---|---|---|
| 1 | pending 상태에서 yes/no가 아닌 새 발화 | pending 폐기 후 일반 파이프라인, 안내 없음 | `이전 확인을 취소하고 새 조건을 적용했어요` 같은 명시 안내 필요? |
| 2 | budget만 단독 슬롯 (예: "5천만원만") | need_more 1개로 처리 | `예산만으로는 검색이 어려워요` 같은 별도 분기 필요? |
| 3 | 슬롯 다수인데 매치 0 | B7 일반 안내 | 어떤 조건을 빼면 매칭되는지 힌트 (예: `예산 제약을 풀면 12개 매치`) 가능 |
| 4 | 동일 코드 재입력 (이미 "강남"인데 다시 "강남") | 충돌 아님, 변화 없이 list/need_more 반환 | `이미 적용된 조건이에요` 명시 필요? |
| 5 | confirmation 없을 때 사용자가 "예/아니오"만 입력 | 일반 발화 → 추출 0 → B4 | 자연스러우나, 한 턴 낭비. 별도 처리 필요한가? |
| 6 | 세션 만료/삭제 후 메시지 전송 | filter_context = None, 새 세션처럼 동작 | `세션이 만료됐어요` 안내 필요? |
| 7 | SSE 도중 네트워크 끊김 | F11 `오류: ...` toast + 에러 버블 | 재시도 버튼 / 자동 재연결 |
| 8 | LLM 추출이 timeout/실패 | B8 에러 (예외 문구 그대로 노출) | 사용자 친화적 메시지로 wrap 필요 |
| 9 | 매치 결과는 있는데 가격 정보가 모두 없는 경우 | 정렬은 0으로 처리, 리스트는 표시 | 가격 미기재가 다수일 때 안내 필요? |
| 10 | top_k(20) 초과 시 "더 보기" | 현재 없음, B6a 메시지로만 안내 | 페이지네이션 / 더보기 인터랙션 정의 필요 |

## 7. 응답 페이로드 키 참고

백엔드 SSE 이벤트 `data` JSON 키 (프론트 `V2Message`와 매핑):

| 키 | 타입 | 의미 |
|---|---|---|
| `type` | `"chat" \| "need_more" \| "list" \| "confirmation_required"` | 응답 분류 |
| `message` | string | 본문 텍스트 |
| `items` | `MediaItem[]` | list type 한정 |
| `match_count` | int | 전체 매치 수 |
| `extracted` | object | 이번 턴 추출 결과 (raw codes) |
| `enriched_extracted` | object | 이번 턴 추출 + description |
| `previous_context` | object | 현재 누적 슬롯 (raw) |
| `previous_context_detail` | object | 현재 누적 슬롯 + description |
| `changes` | array | confirmation_required 한정 (변경 diff) |
| `matched_categories` | int | need_more 시 매칭 슬롯 수 |

SSE 이벤트 종류: `message` (본문), `done` (완료), `error` (오류)

## 8. 후속 작업 제안

이 문서를 기반으로 다음 순서로 정리 가능:

1. **5번 불일치 항목 일괄 정비** — 문구만 손보는 단일 패치
2. **6번 누락 케이스 우선순위 선정** — 사용자 영향도 큰 1~3개만 1차 처리
3. **문구 상수화** — 백엔드에 `MESSAGES = {...}` dict 분리하여 한 곳에서 관리
