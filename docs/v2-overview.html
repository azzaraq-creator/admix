OOH 광고 매체 추천 시스템 v2

매체 데이터를 6축 키-밸류 코드(업종/제품/목적/타깃/지역/카테고리)로 사전화하고, LLM이 사용자 발화를 코드로 매핑해 DB AND 필터 + 광고비 정렬로 매체를 즉시 추천합니다. 별도 그래프 노드 없이 단일 LLM 호출로 매우 빠른 응답을 제공하며, 멀티턴으로 조건을 누적·교체합니다.

1.

단일 LLM 호출

발화 1건당 키워드 매핑 LLM 1회만 호출. 그래프 노드/리랭킹 없음 → 응답 1~2초.

코드 기반 매칭

사전 코드(IND-01 등)로만 매칭. 모호한 텍스트 유사도 대신 결정론적 SQL 필터.

세션 영속화

슬롯 상태(filter_context) + 전체 메시지(ad_messages) DB 저장. 새로고침 후 복원.

2.

6축 키워드 사전 + 예산

매체 데이터와 사용자 발화는 모두 코드 단위로 일치시킵니다. 매체에는 카테고리별 코드 배열이 부여돼 있고 (예: loc_codes: ["LOC-01"]), LLM은 발화에서 같은 코드 집합으로 매핑합니다.

축 코드 prefix 설명 / 예시
업종 IND-XX 광고주의 산업/업종. 예: 금융, 명품·럭셔리, 화장품·뷰티.
제품 PRD-XX 광고할 제품군. 예: 스킨케어, 가방·잡화, 식음료.
목적 OBJ-XX 캠페인 목적. 예: 신제품 런칭, 프리미엄 브랜딩, 도달.
타깃 TGT-XX 타깃 오디언스. 예: 10대 후반, 2030 여성, 유동인구 전반.
지역 LOC-XX 광고 지역/상권. 예: 강남역·테헤란로, 성수카페거리, 홍대입구.
카테고리 CAT-XX 매체 카테고리. 예: 빌보드, 지하철, 버스, 옥외전광판.
예산 budget 사전 코드가 아닌 원 단위 정수. LLM이 "5천만원→50000000" 등으로 변환. 상한 필터로만 사용.
왜 코드 기반인가

동의어/오타에 영향을 받지 않습니다. "강남", "강남역", "테헤란로"가 모두 LOC-01로 매핑되고, 매체에 부여된 loc_codes ?| ['LOC-01'] jsonb 연산자 한 번으로 매칭됩니다.

3.

멀티턴 슬롯 머신

세션마다 filter_context(JSONB)에 누적 슬롯과 보류 상태를 저장합니다. 매 발화마다 새 코드를 추출해 기존 슬롯과 병합하되, 세 가지 규칙으로 동작합니다.

1

빈 슬롯 자동 채움

기존에 비어 있던 카테고리는 새 코드를 그대로 받아 들입니다. 예: 이전에 지역만 있었고 새 발화에서 카테고리가 추가됐다면, 카테고리 슬롯이 채워지며 누적됩니다.

2

충돌 감지 → 예/아니오 확인

이미 값이 있는 카테고리에 다른 코드가 들어오면 충돌로 판정해 confirmation_required 이벤트를 보냅니다. 사용자가 "예"라고 답하면 충돌 카테고리만 새 값으로 교체, "아니오"면 기존 유지.

기존에 설정된 조건과 충돌하는 항목이 있어요. 교체할까요? (예/아니오) · 지역: 강남역·테헤란로 → 홍대입구

보류 중에도 비어 있던 다른 카테고리(예: 새 발화로 들어온 budget)는 즉시 적용됩니다. 보류는 충돌 카테고리에만 한정.

3

슬롯 단건 제거 (X 버튼)

상단 슬롯 바의 X 버튼을 누르면 POST /recommend/v2/slot/remove 가 호출됩니다. 해당 (category, code)를 제거하고 남은 슬롯으로 동일 파이프라인을 재실행해 새 매체 리스트(또는 need_more)를 즉시 반환합니다.

  • · 예산 제거: category="budget" → 상한 필터 해제 → 가격 무관 매체 포함
  • · 카테고리 코드 제거: category="loc", code="LOC-01" → 해당 코드만 빼고 재검색
  • · 보류 상태(pending_change)도 함께 폐기 — 사용자가 직접 슬롯을 손볼 때는 yes/no 확인을 우회
4.

DB 필터 + 응답 분기

SQL 필터 — 카테고리간 AND, 내부 OR

각 카테고리에 코드가 1개 이상 있으면 jsonb ?|(any) 연산자로 OR 매칭을 추가하고, 카테고리간에는 AND로 누적합니다. 예산은 별도로 CAST(advertisement_fee AS bigint) ≤ budget 상한 필터를 적용합니다 (가격 미기재는 자동 제외). 

SELECT * FROM media_items
WHERE loc_codes ?| ARRAY['LOC-01']
  AND cat_codes ?| ARRAY['CAT-10']
  AND advertisement_fee IS NOT NULL
  AND advertisement_fee != ''
  AND CAST(advertisement_fee AS bigint) <= 50000000
ORDER BY advertisement_fee DESC
LIMIT 20;

응답 타입 분기 — 매칭 슬롯 수

매칭 수 응답 type 동작
0개 chat 조건이 너무 적어 추천 불가. "지역/제품/카테고리 등을 알려주세요" 안내.
1개 need_more 현재 조건 요약 + "조건 1개 더 알려주세요" 부드러운 추가 질문.
2개 이상 list SQL 필터 → 광고비 내림차순 Top-K(=20). 총 매치 수를 함께 안내.
충돌 시 confirmation_required 충돌 카테고리 + 새 값을 보여주고 예/아니오 응답을 기다림.

예산 슬롯은 매칭 수에 1만큼 포함됩니다. 예산만 단독 → 1개로 카운트되어 need_more.

5.

실제 테스트 케이스

현재 로직으로 실제 발화를 돌려본 결과입니다. 크게 두 부류의 한계가 드러납니다 — 매칭 매체 부족(사전·매체 데이터 미흡)과 매체 데이터 자체의 결함(가격 미기재 등).

A

매칭이 적거나 없음

슬롯 추출은 잘 되지만 해당 조합에 매체가 부족하거나, 키워드 사전에 해당 지역이 없어서 코드 매핑이 실패하는 경우.

사용자 발화 추출 슬롯 결과 원인 분석
"성수 외국인대상으로 광고" 업종 외국인 관광객 / 지역 성수동 1건 외국인 타깃 × 성수 교집합 매체가 1개뿐 (성수 Canvas).
"유아 RFP 들어왔어요 가락 10주 8천만원" 업종 유아·아동 / 지역 수서·가락 / 예산 8천만원 0건 가락 일대에 유아 업종 매체 부재.
"뷰티 RFP 범어 8주 3억" 업종 화장품·뷰티 / 지역 LOC-XX / 예산 3억 0건 지역 사전에 "범어"(대구) 미등록 → LOC 매핑 실패.
"우리 인테리어 매장 코엑스 일대 8주 1천만원" 업종 부동산·건설·인테리어 / 지역 삼성역·코엑스 / 예산 1천만원 0건 예산 슬롯 제거 후에도 0건 → 코엑스 인테리어 매체 자체가 없음.
"우리 스트리밍 매장 익은 일대 2주 1천만원" 타깃 첫쇼핑·쇼핑객 / 카테고리 쇼핑몰 2건 롯데월드몰 2건. 좁은 타깃 × 카테고리 교집합.
"카페 캠페인 활성의 반년 1500만원" 업종 카페·베이커리 / 지역 건대·왕십리 / 목적 지역 인지도강화 0건 목적 슬롯 제거 후에도 0건. 건대·왕십리에 카페 카테고리 매체 부재.
"성수 외국인대상으로 광고" → 1건
"유아 RFP 가락 8천만원" → 0건
"뷰티 RFP 범어 3억" → 0건 (LOC-XX)
"인테리어 코엑스 1천만" → 0건
"스트리밍 매장 익은 1천만" → 2건
"카페 캠페인 건대 1500만" → 0건
공통 원인 — (1) 키워드 사전 미등록 지역/업종 → LOC-XX 같은 placeholder, (2) 해당 조합의 매체가 실제로 부족, (3) 모호한 발화로 슬롯 부분 추출. 사전 확장 + 매체 데이터 보강으로 개선 가능.
B

매체 데이터 라벨링 오류

매체에 부여된 키워드 코드가 잘못 태깅된 경우. 코드 1개가 의미적으로 구분돼야 할 여러 지역을 묶고 있어, 한 지역만 의도한 검색에 엉뚱한 지역 매체가 같이 잡힙니다.

사용자 발화 추출 슬롯 결과 문제
"회현"으로 검색 지역 시청·회현·을지로 하남시청 매체 노출 하남시청 일대 매체에도 같은 시청·회현·을지로 라벨이 부여돼 있어, 서울 회현을 의도한 검색에 하남시청 매체가 매칭됨.
"회현" 검색 → 하남시청 매체가 잘못 매칭
원인 — "시청"이라는 일반 명사가 서울시청과 하남시청 양쪽에 동일 LOC 코드로 묶인 라벨링 결함. 코드 사전 자체보다 매체 측 키워드 태깅이 문제. 동음이의 지역명은 별도 코드로 분리하거나, 매체별 태깅을 재검수해야 함.
