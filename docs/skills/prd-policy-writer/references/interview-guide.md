# 섹션별 인터뷰 질문 가이드

정책서를 함께 채울 때 섹션마다 던질 질문 모음. 한 번에 다 묻지 말고, **한 섹션에 1~2개씩** 골라서 물어보고 답을 받아 초안을 채운 뒤 다음으로 넘어간다. 기획자가 "모르겠다 / 아직 안 정함"이라고 하면 그 항목은 9번 "논의 필요"에 그대로 옮긴다 — 빈칸으로 두지 않는다.

질문은 항상 **기능·정책** 쪽으로 유도한다. "이 버튼 색은?" 같은 디자인 질문은 하지 않는다. "이 버튼을 누르면 어떤 규칙으로 무엇이 일어나나요?"처럼 동작을 묻는다.

## 1. 화면 목적
- 이 화면이 없으면 사용자가 무엇을 못 하나요?
- 이 화면에서 사용자가 끝내 하려는 단 하나의 행동은 무엇인가요?
- 잘 만들어졌다는 걸 어떻게 알 수 있나요? (전환율, 완료율 등 수치가 있으면 좋음)

## 2. 사용자 & 권한 정책
- 이 화면을 쓰는 사용자 등급/상태가 몇 가지인가요? (비회원/회원/등급별 등)
- 각 등급이 할 수 있는 것과 막히는 것은? 한도가 있다면 **정확한 숫자**는?
- 무엇을 1회로 세나요? (예: 발화 1번 = 1회인지, 추천 결과 1건 = 1회인지)
- 한도에 도달하면 화면에서 무슨 일이 일어나나요? (차단/유도/안내)
- 한도는 리셋되나요? (월/일/누적/영구)

## 3. 핵심 기능
- 이 화면의 기능을 동작 단위로 나열하면 무엇무엇인가요?
- 각 기능이 동작하려면 어떤 입력/조건이 먼저 필요한가요?
- 기능이 "되는 경우"와 "안 되는 경우"를 가르는 규칙은?

## 4. 사용자 플로우
- 사용자가 이 화면에 들어와서 결과를 얻기까지의 순서를 말해 주세요.
- 중간에 갈라지는 분기가 있나요? (조건 A면 이쪽, B면 저쪽)
- 잘못된 입력이나 빠진 정보가 있으면 어디로 가나요?

## 5. 화면 상태
- 처음 들어왔을 때(데이터 0개) 무엇이 보이나요?
- 처리 중일 때 사용자에게 무엇을 보여주나요?
- 결과가 없을 때는? 한도를 다 썼을 때는? 에러가 났을 때는?

## 6. 비즈니스 규칙
- 2번·3번에서 나온 숫자와 조건을 개발이 그대로 구현할 수 있게 한 줄씩 못박을 수 있나요?
- "반드시 ~해야 한다 / 절대 ~하면 안 된다"에 해당하는 규칙이 있나요?

## 7. 예외 & 엣지 케이스
- 네트워크/서버 오류 시 어떻게 처리하나요?
- 세션 도중 권한이 바뀌면? (로그인/로그아웃/등급 변경)
- 동시에 여러 번 누르거나 새로고침하면?

## 8. 논의 필요
- 지금 답하면서 "이건 다른 사람과 합의가 필요하다" 싶었던 항목은?
- 디자인/개발에게 되묻고 싶은 것은?

---

## 진행 팁
- 기획자의 원문 표현을 최대한 살린다. 임의로 정책을 지어내지 않는다.
- 숫자·분기·예외는 절대 추측해서 채우지 말고, 불확실하면 9번으로.
- 한 섹션을 채운 뒤 "이렇게 적었는데 맞나요? 빠진 건 없나요?"로 짧게 확인하고 넘어간다.
